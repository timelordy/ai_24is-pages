# 01. GitVerse, GigaCode и постановка проверяемой задачи

**Цель:** Настроить рабочую среду, понять готовый проект и превратить просьбу заказчика в проверяемую задачу до изменения исходного кода.

**Рабочая ветка:** `lab/01-task-context`

## Исходная просьба

> Добавьте фильтр заявок по статусу. Должно быть удобно.

## Задание

1. Примите приглашение GitVerse Lab и откройте свой персональный форк. Если среда уже настроена на вводной встрече, начните со следующего шага.
2. Клонируйте репозиторий, откройте его в VS Code, войдите в GigaCode и выполните `npm test`, затем `npm run start`.
3. Попросите GigaCode кратко объяснить `src/tickets.js` и назвать файлы, связанные с будущим фильтром. Проверьте минимум два утверждения по исходникам.
4. Прочитайте `BRIEF.md`, `REQUIREMENTS.md`, `CHECKS.md` и текущее приложение.
5. Создайте задачу GitVerse по шаблону `gitverse/issue-template.md`. Отделите уже известные требования от решений, которых пока нет.
6. Попросите GigaCode найти неоднозначности, но не писать код. Сформулируйте минимум два содержательных уточняющих вопроса.
7. Зафиксируйте учебный контракт фильтра: `all → [1,2,3,4,5,6]`, `open → [1,3,4,6]`, `closed → [2,5]`, неизвестный статус должен считаться ошибкой.
8. Выполните `git diff --exit-code -- index.html src tests styles.css`: исходный код приложения не должен измениться. Заполните `REPORT.md`.

## Успешный результат

- `npm test` завершается с кодом `0`; проходят все **5 базовых тестов**;
- после `npm run start` на странице видны **6 заявок**, статусы на русском, в консоли браузера нет ошибок;
- в `REPORT.md` записаны **2 утверждения GigaCode** и для каждого указан конкретный файл/функция, которыми оно проверено;
- создана задача GitVerse, где буквально зафиксированы результаты `all`, `open`, `closed` из шага 7 и минимум **2 уточняющих вопроса**;
- команда `git diff --exit-code -- index.html src tests styles.css` завершается успешно: код приложения не изменён.

## Не засчитывается, если

- есть только скрин или текст «GigaCode всё объяснил», но нет проверки по исходникам;
- студент изменил код фильтра уже на этой паре;
- критерии написаны как «фильтр должен работать корректно» без конкретных входов и ожидаемых результатов;
- тесты не запускались лично студентом или отсутствует их реальный вывод.

## Что сдавать

- ссылка на персональный репозиторий и задачу GitVerse;
- `REPORT.md` с двумя проверенными утверждениями AI;
- вывод `npm test`;
- вывод `git diff --exit-code -- index.html src tests styles.css`.

## Индивидуальный вопрос

Чем отличается ответ GigaCode в чате, изменение файла и commit в Git? Какое решение про фильтр агент мог бы додумать сам, если его не уточнить?

## Что принимает преподаватель

- студент может открыть свой репозиторий и объяснить, где лежит логика заявок
- задача GitVerse содержит конкретные ожидаемые ID для трёх режимов
- есть минимум два уточняющих вопроса и два проверенных утверждения AI
- исходный код приложения не изменён
