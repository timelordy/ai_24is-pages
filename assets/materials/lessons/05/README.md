# Пара 5. Локальный MCP: реальные данные через инструмент

**Основная работа:** откройте [`starter/LAB.md`](starter/LAB.md). Нужно проверить 10 прогнозов, 5 живых вызовов и 3 ошибки.

90 минут · один учебный Python-проект · бесплатная обязательная часть.

**Среда:** OpenCode + Groq; MCP и probe работают локально. **Лимит:** до 8 заданий агенту.

## Что изучаем

Подключать read-only MCP, читать схему аргументов, отличать ошибку инструмента от пустого результата.

## Что делаем

Рабочий локальный MCP-конфиг, журнал двух tool calls и двух ошибок, неизменные данные.

## Подготовка и независимый старт

Из корня полного комплекта: `python scripts/start_lesson.py 05 ../my-lesson-05`.
Перейдите в созданную папку. Либо скачайте отдельный starter с портала и распакуйте его.
Не копируйте конфиги поверх своей прошлой работы. [Исходные файлы](starter/START.md) · [Материалы](materials.md).

## Объяснение

MCP стандартизирует обмен между средой и инструментом. Модель выбирает имя и аргументы, сервер валидирует их и возвращает данные. В обязательной части сервер запускается локально через stdio, ничего не слушает в сети и не пишет задачи. Метка readOnlyHint описательная: отсутствие write-кода и проверка данных важнее метки.

## Шаги

1. Выполните python probe_mcp.py: обе функции должны ответить, неизвестный id должен вернуть isError=true.
2. Прочитайте блок mcp в opencode.json. Если python не найден в PATH среды, укажите абсолютный путь из python -c "import sys; print(sys.executable)". Не коммитьте путь своей машины.
3. Запустите opencode mcp list, затем новую сессию OpenCode. Попросите получить задачи todo через tasks_list_tasks, без чтения tasks.json.
4. Попросите get_task для id=2 и id=999. Сохраните имя инструмента, аргументы и реальный ответ.
5. Передайте status=unknown. Объясните, почему ошибка не означает «задач нет».
6. В отдельной копии переименуйте tasks.json, повторите вызов и верните имя. Завершите сессию, убедитесь, что дочерний процесс завершился.

## Что должно получиться

Рабочий локальный MCP-конфиг, журнал двух tool calls и двух ошибок, неизменные данные.

## Проверка и критерии сдачи

- tools/list объявляет только list_tasks и get_task.
- list_tasks(todo) возвращает id 1,2,4; get_task(2) сохраняет null.
- Неизвестный id, неверный статус и недоступные данные дают ошибку.
- Хеш tasks.json не меняется; сетевой аккаунт для MCP не нужен.
