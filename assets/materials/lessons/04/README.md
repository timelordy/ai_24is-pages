# Пара 4. Исправление дефекта с проверкой тестами

**Основная работа:** откройте [`starter/LAB.md`](starter/LAB.md). Сдаётся полный цикл red → diagnosis → patch → green → counterexample.

90 минут · один учебный Python-проект · бесплатная обязательная часть.

## Что изучаем

Воспроизводить ошибку, поручать минимальную правку агенту и проверять её независимыми тестами.

## Что делаем

Минимальный diff sort_tasks, неизменные тесты, падение до и успех после, объяснение ключа сортировки.

## Подготовка и независимый старт

Из корня полного комплекта: `python scripts/start_lesson.py 04 ../my-lesson-04`.
Перейдите в созданную папку. Либо скачайте отдельный starter с портала и распакуйте его.
Не копируйте конфиги поверх своей прошлой работы. [Исходные файлы](starter/START.md) · [Материалы](materials.md).

## Объяснение

Тест фиксирует требование, а не пожелание модели. Сначала наблюдаем падение на исходном коде, затем меняем код, затем запускаем те же тесты. Зелёный результат после удаления проверки ничего не доказывает. Diff показывает границы правки.

## Шаги

1. В новой рабочей папке выполните python -m unittest -v. Сохраните полный вывод падения.
2. Инициализируйте Git и зафиксируйте starter. Прочитайте R3; сформулируйте ожидаемый порядок id.
3. В OpenCode выберите executor. Попросите исправить только sort_tasks в tasks.py; тесты, данные и требования не менять.
4. Прочитайте запрос разрешения edit. Разрешите только tasks.py один раз. Если путь не совпал с правилом, не расширяйте права до всей папки: сверьте путь и конфиг.
5. Вручную запустите те же тесты и python check_integrity.py. Просмотрите git diff -- tasks.py и git diff -- test_tasks.py.
6. Проверьте новый список с одинаковыми сроками, обратным порядком id и пустой список. Сохраните отчёт before/patch/after.

## Что должно получиться

Минимальный diff sort_tasks, неизменные тесты, падение до и успех после, объяснение ключа сортировки.

## Проверка и критерии сдачи

- Исходный starter падает на test_sort_missing_due.
- После правки все 5 тестов проходят без изменения test_tasks.py.
- Защищённые файлы совпадают с manifest; входной список не меняется.
- Для due=null задачи идут последними, при равных датах — по id.

## Что показать преподавателю

Объясните каждый элемент ключа сортировки. Почему нельзя заменить null на сегодняшнюю дату? Запустите тест на входе, который преподаватель даст сейчас.
Сдайте [отчёт](report-template.md), исходные доказательства и свою рабочую папку. Самоотметка на сайте не является оценкой.

## Для сильных

Добавьте собственный regression test с двумя задачами без срока и разными id, не ослабляя исходные проверки.

Если модель недоступна, используйте [резервный маршрут](../../teacher/FALLBACK.md). Непроведённые живые проверки отмечайте NOT_RUN.
