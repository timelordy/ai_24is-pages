Пара 3. Собственный skill проверки требований

Основная работа: откройте starter/LAB.md. Skill испытывается на трёх входах и в сломанном состоянии.

90 минут · один учебный Python-проект · бесплатная обязательная часть.

Что изучаем

Оформлять повторяемую процедуру как Agent Skill и доказывать её загрузку.

Что делаем

Свой SKILL.md, таблица R1–R6 и журнал загрузки, один опыт с ошибкой обнаружения.

Подготовка и независимый старт

Из корня полного комплекта: python scripts/start_lesson.py 03 ../my-lesson-03. Перейдите в созданную папку. Либо скачайте отдельный starter с портала и распакуйте его. Не копируйте конфиги поверх своей прошлой работы. Исходные файлы · Материалы.

Объяснение

Skill — папка с SKILL.md: frontmatter name/description и процедура в Markdown. Он не является отдельной моделью или обязательным исполняемым кодом. Среда сначала видит описание, затем загружает содержание при вызове skill. Один и тот же навык можно применять к новым входным данным.

Шаги

  1. Изучите готовый skill и REQUIREMENTS.md. Своими словами перепишите описание и добавьте один проверяемый шаг для R3.
  2. Перезапустите OpenCode в starter после изменения skill.
  3. Попросите «Загрузи skill requirements-check и проверь R1–R6 по файлам. Не утверждай, что запускал тесты».
  4. Сохраните событие skill, последующие read и таблицу требований. Сверьте ссылки на функции.
  5. В новой сессии сравните результат с обычным запросом без явного skill. Не считайте отсутствие явного запроса доказательством отсутствия автозагрузки: смотрите журнал.
  6. В копии папки испортите name в frontmatter, повторите обнаружение и восстановите файл. Опишите причину и проверку.

Что должно получиться

Свой SKILL.md, таблица R1–R6 и журнал загрузки, один опыт с ошибкой обнаружения.

Проверка и критерии сдачи

  • name совпадает с requirements-check; description объясняет, когда использовать skill.
  • Есть событие skill(name=requirements-check), затем чтение реальных файлов.
  • R3 проверяется по sort_tasks; предположение по чтению отделено от результата теста.
  • В отчёте нет выдуманного успешного запуска.

Что показать преподавателю

Какая часть skill переиспользуется? Где доказательство, что он загружался? Почему фраза «я использовал skill» не достаточна? Сдайте отчёт, исходные доказательства и свою рабочую папку. Самоотметка на сайте не является оценкой.

Для сильных

Добавьте отдельный fixture с нарушением R1 и проверку, которая отличает неверные данные от ошибки алгоритма.

Если модель недоступна, используйте резервный маршрут. Непроведённые живые проверки отмечайте NOT_RUN.
