# С чего начать

На сайте курса откройте первую работу и идите по карточкам. На каждом шаге видно, где действовать, что попросить у агента и какой результат проверить. Опыт с Git и терминалом не требуется.

Студенческие материалы всех шести работ 01–06 разрешены к публикации. Интерфейс ведёт последовательно по предыдущим обязательным работам и обязательным шагам; необязательная 05 не блокирует 06. Отметки хранятся локально в этом браузере отдельно для выбранной группы и не означают оценку или принятие работы преподавателем. Такая навигация не защищает публичные файлы от прямого скачивания и не создаёт серверного контроля доступа.

Курс «Методы искусственного интеллекта» учит работать с агентом на одном учебном сайте Campus ServiceDesk. Вы ставите задачу, уточняете план, смотрите результат, возвращаете ошибку на исправление и объясняете одно решение. Готовое сообщение ИИ само по себе работу не завершает.

## Первое занятие

1. По карточкам установите Git, VS Code, **Node.js не ниже 22.13.0** и OpenCode V1.

   Git сохраняет историю версий, VS Code открывает файлы, Node.js запускает сайт и поздние этапы со встроенным SQLite, OpenCode выполняет задачи с помощью модели ИИ.

2. Скачайте проект и откройте в VS Code папку с `package.json`. По шагам 8–9 подключите OpenCode, проверьте файлы подготовки и создайте рабочую ветку.

   Что означают названия подключения, объяснено ниже и перед действиями на шаге 8. **Секретный ключ вводите только в поле авторизации помощника.**

3. По шагу 10 попросите агента запустить сайт. Прочитайте предложенную команду, разрешите запуск и откройте адрес из ответа. В браузере должны появиться **12 заявок**.

   Затем поставьте свой вопрос о сайте и самостоятельно проверьте ответ по файлам или в браузере. **Код приложения на первой работе сохраняем без изменений.**

4. Коротко опишите свою работу с агентом и проверенный результат. Можно написать самому или с помощником, в удобной форме и объёме.

   `REPORT.md` содержит **необязательную заготовку**; сохранение заметки в Git показано как один из способов.

`TASK.md` можно скачать как памятку или передать агенту. В `REPORT.md` есть необязательные подсказки для заметки. Читать эти файлы целиком до первого действия не нужно: маршрут есть на странице.

### OpenCode, Inception и Mercury 3: зачем три названия

В ChatGPT или Claude можно написать вопрос и получить ответ ИИ.

- В курсе похожий разговор ведём в **OpenCode**, программе на вашем компьютере. Она умеет ещё читать файлы проекта и выполнять разрешённые действия.
- **Mercury 3** составляет ответы. Это модель ИИ, по назначению похожая на модели в ChatGPT или Claude.
- **Inception** предоставляет доступ к этой модели через интернет; такой сервис называют **провайдером**. Mercury 3 работает на серверах Inception, а не скачивается целиком на ваш компьютер.

Например, вопрос «Где хранятся заявки?» вы вводите в OpenCode. Программа отправляет запрос модели через Inception и показывает ответ.

Содержимое прочитанных агентом файлов может отправляться вместе с вопросом как **контекст**, то есть информация для ответа. Это не отправка всей папки автоматически. **Используйте учебные данные, не передавайте пароли и персональные сведения.**

Через Google вы только входите в кабинет Inception. Затем получаете **API-ключ**, секрет для доступа программы к сервису от вашего аккаунта. **Ключ вставляют в поле авторизации OpenCode, а не в переписку или файлы.**

**Оплата для прохождения курса не требуется:** если сервис просит платёж или недоступен, используйте запасной вариант с преподавателем.

- Если `package.json` не найден, проверьте открытую папку.
- Если заблокирован `npm.ps1`, выберите в меню терминала **«Command Prompt / Командная строка»** или используйте `npm.cmd start`.
- При ошибке сохраните её текст и попросите агента объяснить причину **до правки**.

## Второе занятие: своя копия и поиск

Создайте свой форк Campus-ServiceDesk на GitVerse и подключите к нему прежнюю папку.

- **Fork** создаёт копию в аккаунте, **Clone** скачивает её на компьютер.
- Если папка сохранилась с первого занятия, **повторное клонирование не нужно**.
- Сохраните прежнюю заметку **до переключения ветки**; её имя и место могут быть любыми.

1. Опишите, что человек должен сделать на сайте и увидеть. Дайте агенту границы, обсудите план и разрешите согласованную правку.
2. В VS Code откройте **«Управление версиями»** и сравните старые и новые строки. Это сравнение называется **diff**.
3. Затем сами выполните сценарий в браузере.

Автоматические тесты может запускать агент: при ошибке попросите объяснение и откройте указанное место. Количество успешных тестов не является целью занятия.

На этой работе добавляем **только поиск по заголовку, описанию и месту**.

- Пустое поле показывает 12 заявок;
- «ПРОЕКТОР» и «305» находят №101;
- слово без совпадений показывает 0 и сообщение.
- Очистка возвращает 12 заявок.

После исправления повторите проверку, сохраните выбранные файлы коммитом и отправьте `feature/frontend-query` в свой форк. Покажите ссылку на коммит и работающий поиск, объясните одно решение.

Заметка **необязательна**. Фильтры, сортировка, Issue, запрос на слияние и CI для сдачи работы 02 **не нужны**.

## Следующие занятия

Работу 03 начинайте от принятого преподавателем коммита поиска, даже если он пока в `feature/frontend-query`, а не в `main`. В каждой следующей работе указано, что добавить в приложение и как проверить результат. Перед новой работой сохраняйте прежние записи и обновляйте только нужные документы. Новое приложение поверх своей папки не копируйте.

В календаре подгруппы шесть работ объединены в три или четыре занятия; **комментарии 05, Issue/MR/CI и расширенные отчёты не входят в общий сокращённый минимум**.

- На готовой основе преподавателя проверяем форму/API и сохранение в SQLite после остановки и запуска с тем же файлом БД.
- **AI-подсказка внутри приложения** появляется только на финальном занятии: предложение, явное применение и ручное создание при отказе.
- **OpenCode** доступен с первого занятия.

Комплекты H3/H4 подготовлены локально как полные рабочие примеры foundation/final, но **их выдачу отдельно разрешает преподаватель**.

**Не распаковывайте их поверх своего проекта и не подменяйте ими собственный поиск.** Интеграцию выполняйте с преподавателем, сохраняя свои тесты, заметки, настройки и историю.

Предоставленный код не засчитывается как самостоятельно написанный. `REPORT` остаётся **необязательным**.

1. Сначала распакуйте выданный комплект в отдельную пустую внешнюю папку для проверки человеком.
2. Для **Plan** нужна новая справочная копия `_teacher-reference/foundation` или `_teacher-reference/final` внутри собственного проекта, **не поверх `src`/`backend`**.
3. **До копирования** добавьте строку `/_teacher-reference/` в локальный `.git/info/exclude`, сохранив весь прежний текст. **Существующую справочную папку не перезаписывайте.**
4. Из корня проекта проверьте `git check-ignore _teacher-reference/foundation/manifest.json` (для final: `git check-ignore _teacher-reference/final/manifest.json`) и `git status --short --untracked-files=all`: путь должен игнорироваться, справочная копия не должна появляться в status.
5. Запускайте OpenCode из этого же корня; передавайте явные внутренние пути к manifest и diff по [TASK 03](lessons/03/TASK.md) или [TASK 06](lessons/06/TASK.md).

Справочные данные **не запускают, не сдают, не добавляют в Git и не используют как настройки/permissions**. `external_directory=deny`, config, `.gitignore` и глобальные ignore сохраняются.

**При запрете read не обходите его:** преподаватель перенесёт согласованные фрагменты вручную.

## Если помощник не отвечает

Внутри OpenCode введите `/models` и выберите доступный **OpenCode Free**. **NVIDIA** подключайте через `/connect` личным ключом после проверки с преподавателем.

При смене модели сообщите задачу, рабочую ветку, изменённые файлы и последнюю ошибку. Сначала попросите прочитать текущее состояние.

При полном отсутствии связи разберите обезличенный ответ преподавателя и проверьте его локально. Укажите источник и невыполненные действия в отчёте. Этот разбор не выдавайте за свою сессию. Ключи не вставляйте в чат, отчёт или файлы проекта.

## Что покажете преподавателю

Запросы, ход работы и решения могут различаться; обязательных трёх фактов, уточнения, найденной ошибки, версий программ или конкретного формата отчёта нет.

На следующих работах применяются критерии их TASK: сценарий на сайте, работа с агентом, проверка изменений и объяснение решения.

## Преподавателю: локальный просмотр

- В корне репозитория курса `npm run build` собирает публичные материалы в `public/` по `release.json` и закрытые комплекты в `dist/handoffs/`. Для согласованного выпуска всех шести работ нужны `releasedThrough: 6` и `policy: "sequential-progress"`. `npm run preview` открывает портал на `http://127.0.0.1:4173`.
- Для отдельного служебного preview выполните `npm run build:preview`, затем `npm run preview:full` и откройте `http://127.0.0.1:4174`.

Эти команды требуют **Python 3.11+** с именем `python3`; в PowerShell при блокировке `npm.ps1` используйте `npm.cmd`.

Изолированный `--preview` пишет в `qa-output/full-course-preview/`, не меняя `public/`, `dist/` или `release.json`.

**Preview и `dist/handoffs/` содержат закрытые материалы.** Их подготовка не разрешает публикацию или выдачу без отдельного решения преподавателя. `teacher/`, hidden tests, исходные `semester/`, reference и checkpoints, `dist/` и QA-материалы остаются закрытыми. Согласованный выпуск студенческих материалов 01–06 отменяет ожидание завершения предыдущей работы во всех подгруппах. Он не даёт постоянного разрешения на push, создание удалённых репозиториев или будущие публикации.

Полная проверка из корня: `npm run check`; **результат нужно прочитать, а не считать успешным заранее**.
