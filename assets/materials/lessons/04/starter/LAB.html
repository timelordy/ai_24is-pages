Лабораторная 4. Исправляем дефект с доказательством

Результат за 90 минут

Вы пройдёте полный цикл red → diagnosis → patch → green → counterexample. Предмет сдачи — не строка кода, а доказательство причины и отсутствия побочного изменения.

00–20. Red и гипотезы

Запустите python -m unittest -v, сохраните traceback и свяжите падение с R3. Запишите три возможные причины. Для выбранной гипотезы сформулируйте прогноз, который можно проверить до изменения кода.

20–45. Ограниченная правка

В plan mode попросите план. Затем разрешите executor изменить только tasks.py. Не разрешайте правки test_tasks.py, tasks.json и требований. Просмотрите diff построчно и объясните назначение каждой изменённой части.

45–70. Проверка границ

Повторите исходные тесты. Отдельно проверьте пустой список, одинаковые даты, несколько null, обратный порядок id и неизменность входного списка. Добавьте собственный regression test, который падал бы на исходной реализации.

70–90. Контрпример и защита

Попросите модель найти контрпример к патчу, затем проверьте его вручную. На защите преподаватель даст новый список задач. Объясните каждый элемент ключа сортировки до запуска.

Работа не принимается, если изменены ожидаемые значения или защищённые тесты.
