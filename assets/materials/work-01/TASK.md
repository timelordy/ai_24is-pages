# 1. Запускаем проект и проверяем ответы ИИ

**Цель:** Запустить готовый сайт с 12 заявками, разобраться в его коде с GigaCode и проверить три утверждения из ответа. Код приложения на этой работе не меняем.
**Рабочая ветка:** `stage/01-discovery`

## Что делаем

Наш проект — Campus ServiceDesk, сайт с заявками. Например: в аудитории не работает проектор, сломался стул или нужен доступ в помещение. Сейчас на сайте есть 12 готовых заявок. В следующих работах будем добавлять возможности в этот же проект.

На первой работе запускаем то, что уже есть. Потом просим GigaCode объяснить код, проверяем ответ и записываем выводы. Не просим ИИ «сделать всё приложение».

Для вводной встречи достаточно шагов 1–9. Отдельный отчёт за вводную не нужен. Полная первая работа — шаги 1–13 и отчёт, сохранённый в локальном коммите.

## Часть 1. Создать аккаунт GitVerse

Аккаунт GitVerse нужен для подключения GigaCode в VS Code. Работать с кодом, отчётом и требованиями будем на своём компьютере.

1. Откройте [GitVerse](https://gitverse.ru/) и нажмите **«Вход в сервис»**.
2. Войдите доступным способом. Если аккаунта нет, выберите GigaID и зарегистрируйтесь.
3. Задайте имя пользователя и подтвердите почту, если сервис попросит.
4. Не создавайте отдельный репозиторий, задачу или Pull Request для этой работы.

**Проверка:** вы вошли в GitVerse и сможете использовать эту учётную запись при подключении GigaCode.

## Часть 2. Установить Git

Git нужен, чтобы скачать проект и сохранять изменения. GitVerse — сайт, Git — программа на компьютере.

1. Откройте [страницу Git для Windows](https://git-scm.com/install/windows).
2. Для обычного Windows-компьютера скачайте **x64 Setup**.
3. Установите Git. Стандартных параметров достаточно.
4. Закройте и заново откройте терминал. Если VS Code уже запущен — перезапустите и его.
5. Введите команду и нажмите Enter:

```bash
git --version
```

**Проверка:** появился номер версии. Если написано, что команда не найдена, сначала перезапустите терминал. Случайные команды из интернета для этого не нужны.

## Часть 3. Установить Visual Studio Code

Нужен **Visual Studio Code**, он же **VS Code**. Не Visual Studio — это другая программа.

1. Откройте [страницу загрузки VS Code](https://code.visualstudio.com/Download).
2. Для своего Windows-компьютера выберите **User Installer x64** и установите редактор.
3. Запустите VS Code.
4. В верхнем меню выберите **Terminal → New Terminal**. В русской версии — **Терминал → Создать терминал**. Внизу появится строка, куда будем вводить команды.
5. Введите:

```bash
code --version
```

**Проверка:** VS Code открыт, терминал есть, команда показывает версию. Если `code` не найден, закройте VS Code и откройте заново.

## Часть 4. Установить Node.js

Node.js запускает наш проект и его тесты. Вместе с ним устанавливается npm — через него будем вызывать команды проекта.

1. Откройте [страницу Node.js](https://nodejs.org/en/download).
2. Выберите **Node.js 22** для Windows, архитектуру x64 и установщик `.msi`. Курс проверяется на Node.js 22; нужен Node.js 22 или новее.
3. Завершите установку и перезапустите VS Code.
4. В терминале VS Code выполните команды по очереди:

```bash
node --version
npm --version
```

**Проверка:** обе команды показывают версии. Если на Windows PowerShell пишет, что запуск `npm.ps1` запрещён, откройте в VS Code терминал **Command Prompt / Командная строка** и повторите команду. Менять политику безопасности всего компьютера не нужно.

## Часть 5. Установить GigaCode в Visual Studio Code

GigaCode — помощник внутри редактора. Отдельное окно с чат-ботом в браузере не заменяет расширение.

1. Откройте [инструкцию по установке GigaCode](https://gitverse.ru/features/gigacode/install/).
2. Выберите **Visual Studio Code** и скачайте расширение `.vsix`.
3. В VS Code нажмите `Ctrl+Shift+X` — откроются расширения.
4. Нажмите `...` вверху этого раздела → **Install from VSIX...** и выберите скачанный файл.
5. Если редактор предложит перезапуск — перезапустите его.
6. Нажмите **Connect GigaCode**, подтвердите подключение в браузере через свой GitVerse и вернитесь в VS Code.
7. Откройте чат GigaCode и отправьте простой вопрос: «Ответь одним предложением: для чего нужен Git?»

**Проверка:** GigaCode отвечает в VS Code. В версии на скриншотах подключение обозначено как `Ready`. Название и положение индикатора могут отличаться. Важен реальный ответ, а не просто установленное расширение.

## Часть 6. Подготовить папку для проекта

Проект будет работать на вашем компьютере. Заранее выберите обычную папку, которую легко найти, например `Документы\Учеба`.

1. Создайте папку для учебных проектов.
2. Убедитесь, что в пути нет временных каталогов и папки облачной синхронизации.
3. Не сохраняйте в проект пароли, токены и личные данные.

**Проверка:** вы знаете, куда сохраните Campus ServiceDesk, и можете открыть эту папку в Проводнике.

## Часть 7. Скопировать проект и открыть его в VS Code

Не создаём пустой проект и не просим GigaCode написать его с нуля. Берём готовый Campus ServiceDesk и дальше работаем только с локальной папкой.

1. В VS Code нажмите `Ctrl+Shift+P` и выберите **Git: Clone**.
2. Вставьте адрес публичного проекта:

```text
https://gitverse.ru/ultra_turbo_killer/Campus-ServiceDesk.git
```

3. Выберите подготовленную папку на своём компьютере. Для публичного проекта пароль не нужен.
4. После скачивания нажмите **Open / Открыть**.
5. В левой панели должны быть `package.json`, `src`, `server.mjs` и `REPORT.md`. Если их нет, открыта не та папка.
6. Откройте терминал VS Code и выполните `git status`.

**Проверка:** `git status` работает без ошибки, а проект открыт локально в VS Code.

**Если клонирование не работает:** скачайте стартовый архив в разделе «Файлы», распакуйте его и откройте папку с `package.json`. Для шагов с локальной веткой в распакованной папке сначала выполните `git init`, `git add .` и `git commit -m "start project"`.

## Часть 8. Создать рабочую ветку

Ветка — отдельная линия изменений. Основную версию `main` пока не трогаем. Этот шаг выполняем в проекте, скачанном через Git, а не в распакованном архиве.

В терминале VS Code выполните:

```bash
git switch -c stage/01-discovery
git branch --show-current
```

**Проверка:** последняя команда вывела `stage/01-discovery`.

Если Git пишет, что ветка уже существует, вы создавали её раньше. Просто переключитесь:

```bash
git switch stage/01-discovery
```

## Часть 9. Запустить тесты и приложение

Все команды ниже вводим в терминале VS Code. Перед запуском проверьте, что открыта папка с `package.json`.

1. Запустите тесты:

```bash
npm test
```

2. Должны пройти **5 тестов**. В этой стартовой версии нет внешних зависимостей: отдельный `npm install` и сборка не нужны.
3. В этом же терминале запустите приложение:

```bash
npm run start
```

4. Откройте адрес из терминала. Для этой версии проекта это [http://127.0.0.1:4173](http://127.0.0.1:4173).
5. Проверьте, что видно **12 заявок**.
6. Нажмите `F12` → **Console**. Красных ошибок быть не должно.

**Проверка:** тесты прошли, сайт открывается, видно 12 заявок. Поиск, серверное API и база данных появятся в следующих работах. Сейчас не нужно их «чинить» или добавлять.

Пока сервер работает, терминал занят. Для следующих команд откройте ещё один терминал кнопкой `+`. Остановить сервер можно через `Ctrl+C`.

**Если не запускается:** сохраните полный текст ошибки. `package.json` не найден — проверьте папку. Адрес занят — проверьте, не запущен ли ваш сервер в другом терминале. Не просите GigaCode переписать весь проект из-за ошибки запуска.

## Часть 10. Попросить GigaCode объяснить код и проверить ответ

Теперь используем ИИ по делу: чтобы разобраться в чужом коде. Менять файлы пока нельзя.

Откройте чат GigaCode в VS Code и отправьте:

```text
Не изменяй файлы и не выполняй команды, которые меняют проект.
Прочитай src/data.js, src/tickets.js, src/app.js, server.mjs и docs/REQUIREMENTS.md.
Объясни простыми словами:
1. Откуда берутся заявки?
2. Где проверяется правильность данных заявки?
3. Где формируется интерфейс?
4. Что делает server.mjs?
5. Какие ограничения записаны в REQUIREMENTS.md?
К каждому ответу приложи путь к файлу и имя функции или фрагмент кода.
Если не нашёл ответ в файлах, так и напиши. Не придумывай.
```

Выберите **три утверждения** из ответа. Для каждого откройте указанный файл и найдите подтверждение. Если ИИ сослался на несуществующую функцию или неправильно объяснил код, это тоже результат — запишите ошибку.

В `REPORT.md` для каждого утверждения заполните: что сказал GigaCode → где проверили → верно или нет → почему. Пересказ ответа ИИ без проверки не подходит.

**Проверка:** вы можете сами открыть три места в коде и объяснить, подтверждают ли они ответ GigaCode.

## Часть 11. Записать требования к следующей работе

На следующей работе добавим поиск, фильтры и сортировку. Сейчас ничего не реализуем, а записываем ожидаемый результат локально.

1. Откройте `REPORT.md` в VS Code и найдите раздел **«Требования этапа 02»**.
2. Проверьте и отметьте примеры. Числа в квадратных скобках показывают заявки, которые должны остаться после фильтрации.

```text
Статус new → [101,104,107,108,112]
Приоритет high → [101,102,107,108]
Поиск "проектор" → [101]
Поиск "305" → [101]
Статус new + приоритет high → [101,107,108]
Поиск без совпадений → []
Неизвестный status / priority / sort → ошибка
Исходный массив заявок не должен изменяться
```

3. В этом же разделе запишите, что в работу не входят HTTP API, база данных, авторизация и новые внешние библиотеки.

**Зачем это нужно:** «поиск работает нормально» нельзя проверить одинаково. «Поиск “проектор” возвращает заявку 101» можно.

**Проверка:** требования сохранены в локальном `REPORT.md`, и вы понимаете каждый пример.

## Часть 12. Проверить, что код приложения не менялся

GigaCode должен был только читать файлы. Сравним код с основной веткой `main`. Команда ниже видит в том числе изменения, которые уже добавлены в Git или закоммичены в рабочей ветке.

```bash
git diff --exit-code main -- index.html src server.mjs tests styles.css package.json
```

**Проверка:** команда завершилась успешно и ничего не вывела.

Дополнительно проверьте, не появились ли новые файлы кода:

```bash
git status --short -- index.html src server.mjs tests styles.css package.json
```

Здесь тоже не должно быть вывода. Затем посмотрите все изменения:

```bash
git status
```

Изменённый `REPORT.md` — нормально. Изменённые файлы приложения или новые файлы кода — нет. Если они появились, разберитесь с преподавателем, что изменилось. Не удаляйте всё командой сброса наугад.

## Часть 13. Заполнить отчёт и сохранить локальный коммит

1. Откройте `REPORT.md` и заполните шаблон: результаты запуска, три проверенных утверждения GigaCode и требования к следующей работе.
2. Сохраните файл через `Ctrl+S`.
3. Добавьте в Git **только отчёт** и создайте локальный коммит:

```bash
git add REPORT.md
git commit -m "docs: complete stage 01 report"
```

Если Git пишет `Author identity unknown`, один раз настройте имя и учебную почту только для этой папки. `--global` на общем компьютере не используйте.

```bash
git config user.name "Ваше имя"
git config user.email "student@example.com"
```

После настройки повторите `git commit`. Отправлять ветку на GitVerse в этой работе не нужно.

4. Проверьте локальный результат:

```bash
git status
git log -1 --oneline
```

**Проверка:** `git status` сообщает, что рабочая папка чистая, а последняя строка истории содержит ваш коммит с отчётом.
