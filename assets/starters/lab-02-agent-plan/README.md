# 02. Агент исследует репозиторий и составляет план

**Цель:** Отделить чтение и планирование от выполнения и проверить, на чём основан план.

**Рабочая ветка:** `lab/02-agent-plan`

## Задание

1. Создайте ветку и зафиксируйте чистое состояние проекта.
2. При доступе к GitVerse Sessions выберите агента **Plan**. Иначе используйте GigaCode в VS Code и явно запретите изменение файлов.
3. Попросите прочитать `TASK.md`, `REQUIREMENTS.md`, `CHECKS.md`, `index.html`, `src/app.js` и `src/tickets.js`.
4. Требуйте от агента указывать путь к файлу для каждого существенного утверждения.
5. Получите план реализации фильтра. В плане должны быть явно названы контракт функции `filterTicketsByStatus(tickets, status)`, затрагиваемые файлы, тесты и ручные проверки.
6. Проверьте план сами. Добавьте или исправьте минимум один пункт, который агент пропустил или сформулировал неточно.
7. Выполните `git status --short` и `git diff --exit-code -- index.html src tests styles.css`.
8. Сохраните финальный план и доказательство отсутствия изменений в `REPORT.md`.

## Рекомендуемый запрос

```text
Исследуй проект и подготовь план фильтра по статусу.
Прочитай TASK.md, REQUIREMENTS.md, CHECKS.md, index.html, src/app.js и src/tickets.js.
Подтверждай выводы путями к файлам. Не изменяй файлы.
В плане укажи контракт filterTicketsByStatus(tickets, status), изменяемые файлы,
тестовые случаи all/open/closed/unknown и ручные проверки UI.
```

## Успешный результат

Финальный план считается достаточным только если в нём одновременно есть:

- контракт: `all → [1,2,3,4,5,6]`, `open → [1,3,4,6]`, `closed → [2,5]`, неизвестный статус → `RangeError`;
- список предполагаемых изменений: **`index.html`, `src/app.js`, `src/tickets.js`, `tests/filter.test.mjs`**; дополнительный файл допустим только с объяснением;
- проверка того, что входной массив не мутируется;
- команды `npm test` и `npm run start`;
- ручные UI-проверки: «Все = 6», «Открытые = 4», «Закрытые = 2», ошибок в консоли нет;
- минимум **1 исправление плана студентом** с объяснением причины;
- `git diff --exit-code -- index.html src tests styles.css` возвращает код `0`.

## Не засчитывается, если

- план ограничивается фразами вроде «добавить фильтр, обновить UI, написать тесты» без конкретных файлов и ожидаемых значений;
- агент изменил исходный код;
- студент не может показать, какое место плана он проверил или исправил;
- проверка заканчивается сообщением агента «всё должно работать», а не командами и сценариями.

## Что сдавать

- `REPORT.md` с исходным и финальным планом;
- отмеченное собственное исправление студента;
- вывод `git diff --exit-code -- index.html src tests styles.css`.

## Индивидуальный вопрос

Почему фраза «я прочитал файл» недостаточна без события инструмента, ссылки на файл или проверяемой детали?

## Что принимает преподаватель

- план содержит точный контракт и ожидаемые ID
- названы конкретные файлы и проверки
- студент исправил минимум один пункт плана
- `git diff` пуст
