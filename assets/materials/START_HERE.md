# Студенту: как начать

## Что понадобится

1. Аккаунт GitVerse.
2. Ссылка-приглашение на задание GitVerse Lab.
3. Git, Node.js 20+ и VS Code на учебном ПК.
4. GigaCode для VS Code и выполненный вход.

Никаких API-ключей преподавателя, банковских карт и общих паролей. Если GigaCode Sessions недоступны вашему аккаунту, работайте через GigaCode в VS Code: критерии задания от этого не меняются.

## В курсе 6 обязательных работ

У 24ИС02/2 и 24ИС03/1 есть дополнительная вводная встреча для настройки среды. Она не считается отдельной лабораторной. Все подгруппы выполняют одинаковые шесть обязательных работ.

## Сначала найдите Definition of Done

В каждом `TASK.md` есть блок **«Успешный результат»**. Прочитайте его **до запуска агента**.

Если там написано:

```text
open → [1,3,4,6]
closed → [2,5]
npm test → 10 тестов PASS
```

то работа не считается выполненной, пока эти значения реально не получены. Фраза GigaCode «готово» ничего не доказывает.

Рядом находится блок **«Не засчитывается, если»** — это список типичных ложных успехов.

## Обычный цикл работы

```text
получить персональный форк
→ прочитать TASK.md и Definition of Done
→ создать ветку
→ записать ожидаемый результат
→ дать агенту контекст и получить план
→ выполнить ограниченное изменение
→ посмотреть git diff
→ запустить npm test
→ проверить точные сценарии из TASK.md
→ commit и push
→ дождаться нужного CI
→ Merge Request, если требуется
→ объяснить результат своими словами
```

## Первые команды

```bash
git clone <адрес вашего персонального форка>
cd <папка репозитория>
npm test
npm run start
```

Откройте адрес, который покажет сервер. Не открывайте рабочие документы, домашнюю папку или чужие репозитории агенту. Для курса используются только синтетические данные.

## Что считается доказательством

- конкретный вход и конкретный фактический выход;
- реальный `git diff`;
- реальный вывод `npm test`;
- зелёный CI именно на том commit, который сдаётся;
- воспроизведённый сценарий в браузере;
- ссылка на задачу/ветку/Merge Request, если они требуются;
- ваше объяснение решения и непроверенных рисков.

## Что доказательством не является

- «у меня визуально вроде работает»;
- сообщение агента «все тесты прошли» без реального вывода;
- зелёный CI от старого commit;
- скриншот без возможности воспроизвести результат;
- ответ AI, который студент не может объяснить.

Каждая обязательная работа имеет собственный starter. Если предыдущая работа пропущена, используйте starter текущей пары и не пытайтесь вручную восстанавливать промежуточное состояние.
