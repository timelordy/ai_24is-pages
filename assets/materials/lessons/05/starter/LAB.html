Лабораторная 5. Подключаем и испытываем локальный MCP

Результат за 90 минут

Вы проверите контракт read-only MCP двумя способами: напрямую через SDK и через настоящие tool calls агента. Итог — каталог успешных ответов и ошибок, а не демонстрация одной команды.

Среда и лимит: OpenCode + Groq; до 8 заданий агенту. Локальные probe_mcp.py и тесты квоту модели не расходуют.

00–20. Десять прогнозов

Прочитайте схемы list_tasks и get_task. До запуска составьте 10 вызовов: корректные статусы, пустой результат, существующий и неизвестный id, неверные типы и лишний аргумент. Для каждого запишите ожидаемый тип результата.

20–45. Сервер без LLM

Выполните python probe_mcp.py. Проследите initialize, tools/list и calls. Убедитесь, что объявлены только две read-only функции, сервер не слушает сеть и не содержит записи в tasks.json.

45–70. Пять живых tool calls

Подключите MCP в OpenCode. Запретите агенту читать tasks.json напрямую. Выполните минимум пять разных запросов и сохраните имя tool, аргументы, ответ и объяснение модели. Сверьте данные с исходным файлом уже после вызовов.

70–90. Ошибки и восстановление

Проверьте неверный status, неизвестный id и временно отсутствующий tasks.json. Различите пустой список и isError. Верните файл, повторите smoke, завершите процесс и выполните python check_integrity.py.

Работа не принимается, если модель просто пересказала tasks.json без tool event.
