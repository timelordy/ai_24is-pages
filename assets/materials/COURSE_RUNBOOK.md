# Регламент Campus ServiceDesk

## Учебная модель

Это один накопительный проект, а не коллекция лабораторных. Студент должен видеть стоимость изменений в уже существующей системе: контракт прошлого milestone нельзя молча сломать ради следующего.

## Шесть milestones

1. Discovery + проверяемый контракт.
2. Frontend query workspace.
3. REST API.
4. SQLite + workflow + history.
5. Comments + AGENTS.md + skill + MR/CI/review.
6. AI triage boundary + защита.

## Ритм пары

| Минуты | Что происходит |
|---|---|
| 0–10 | Definition of Done, контрольные входы/выходы |
| 10–20 | Один демонстрационный цикл преподавателя |
| 20–60 | Работа агента в feature-ветках |
| 60–75 | tests + ручные сценарии + diff |
| 75–85 | push / CI / MR / review |
| 85–90 | индивидуальный вопрос и фиксация результата |

## Release policy

`release.json` — единственная ручка публикации. Сейчас `releasedThrough = 1`.

Следующий milestone открывается **после завершения предыдущего во всех подгруппах**. Public build должен физически исключать будущие `TASK.md`, `REPORT.md` и recovery files. UI-lock без удаления файлов не считается защитой.

Перед release:

```bash
python scripts/set_release.py N
npm run check
```

Публиковать только зелёный `public/`.

## Recovery

Основной маршрут — персональный накопительный repo. Recovery checkpoint выдаётся только для текущего открытого milestone и содержит состояние **до** него. Студент после recovery создаёт новую ветку и продолжает; автоматического зачёта предыдущих milestone нет.

## Что принимать

Не количество prompt и не красоту ответа модели. Принимать:

- конкретный контракт;
- реальный diff;
- автоматические tests;
- воспроизводимые UI/API сценарии;
- CI именно на сдаваемом commit;
- честно указанные непроверенные риски;
- объяснение студента.

## Стоп-условия

Не засчитывать работу, если студент показывает только сообщение AI, не может воспроизвести результат, CI относится к другому commit, секрет попал в Git или новый milestone сломал обязательный контракт предыдущего.
