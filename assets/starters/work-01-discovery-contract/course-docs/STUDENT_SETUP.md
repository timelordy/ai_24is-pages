# Как подготовить рабочее место

Эта памятка входит в папку учебного проекта. Подробные действия находятся в файле TASK.md и на странице текущей работы сайта курса.

Проектом называем папку с файлами учебного сайта Campus ServiceDesk. Начинаем с готового списка из 12 заявок. На следующих занятиях будем добавлять возможности в эту же папку.

## Какие программы используются

- VS Code открывает файлы проекта. В нём читаем и меняем код.
- Git сохраняет историю версий файлов на компьютере. Сохранённая версия называется коммитом. Отдельная линия изменений называется веткой.
- GitVerse хранит отправленную копию проекта в интернете. Там преподаватель проверяет изменения.
- Node.js запускает код учебного сайта и его проверки. Нужна версия 22 или новее.
- OpenCode помогает разбираться в файлах и менять их с помощью ИИ. Для ответов он подключается к сервису Inception и его модели Mercury. Модель: программа ИИ, которая готовит ответ.

## Сначала откройте и запустите учебный сайт

1. Если программы ещё не установлены, откройте первую работу на сайте курса. Выполните установку по порядку.
2. В VS Code выберите «Файл → Открыть папку». Откройте папку, где находится package.json.
3. В меню выберите «Терминал → Создать терминал». Внизу откроется поле для команд. Вводите по одной команде и нажимайте Enter:

```text
npm test
npm run start
```

Первая команда запускает тесты: автоматические проверки кода. Их можно поручить агенту: попросите показать итог и объяснить ошибку. Вторая запускает учебный сайт. Откройте в браузере адрес, который появился в терминале. Должны быть видны 12 заявок.

Если PowerShell запрещает запуск npm.ps1, используйте `npm.cmd test` и `npm.cmd run start` или откройте в VS Code терминал Command Prompt.

Для скачанного архива настройте историю Git по части 7 первой работы. Там показано, как задать своё имя и создать основную ветку main. Случайные команды настройки Git не нужны.

## Затем установите и подключите помощника

1. В терминале VS Code установите OpenCode V1:

```text
npm.cmd install -g opencode-ai
opencode.cmd --version
```

Должен появиться номер версии. Для курса нужен пакет opencode-ai. Пакет V2 с названием @opencode/cli использует ту же команду; не устанавливайте обе версии одновременно. При другой версии покажите результат преподавателю.

2. Убедитесь, что в папке проекта есть opencode.json. Это готовый файл настроек. В нём уже указаны Inception и Mercury 3, а перед записью файла или запуском команды помощник спрашивает разрешение.
3. Создайте личный аккаунт Inception и ключ API по [официальной инструкции](https://docs.inceptionlabs.ai/get-started). Ключ даёт программе доступ к ИИ от вашего аккаунта. Храните его как пароль.
4. В терминале VS Code введите `opencode.cmd`. Откроется помощник. Теперь команды с косой чертой вводятся внутри него.
5. Введите `/connect`, выберите `Other`, укажите имя подключения `inception` и вставьте личный ключ в поле подключения.
6. Введите `/models` и выберите `inception/mercury-3`. Слово provider в интерфейсе означает сервис, который предоставляет модель ИИ.
7. Внутри OpenCode нажимайте Tab, пока не будет выбран Plan. В этом режиме сначала изучаем проект. Попросите найти файл со списком заявок и назвать его путь. Откройте файл самостоятельно и сравните ответ с содержимым.

На первой работе задайте свой вопрос о сайте, уточните ответ, проверьте три утверждения ИИ по файлам, одно ещё и на экране. Сохраните полезный вывод в отчёте. Менять приложение пока запрещено. В следующих работах после проверки предложенного порядка действий переключайтесь клавишей Tab в Build: режим изменения файлов.

Не вставляйте ключ в opencode.json, отчёт, код, сообщение преподавателю или скриншот. [Описание подключения OpenCode](https://opencode.ai/docs/providers/) и [переключение режимов](https://opencode.ai/docs/agents/).

На 26 октября 2026 года Inception указывает 100 миллионов стартовых бесплатных токенов новым аккаунтам. Токены: единицы учёта объёма текста. Условия и остаток проверяйте в личном кабинете. Доступ из учебной сети и работа всей группы ещё требуют проверки.

## Если помощник не отвечает

Сначала сохраните свои файлы. Внутри OpenCode команда `/models` открывает список моделей. Первый запасной вариант: доступная бесплатная модель OpenCode Free. Список и ограничения меняются.

Второй вариант после проверки преподавателем: сервис NVIDIA. Получите личный ключ, выберите NVIDIA через `/connect`, затем согласованную модель через `/models`. Снова проверьте чтение файла. [Сервисы, которые можно подключить](https://opencode.ai/docs/providers/).

Ошибка 429 означает ограничение запросов или доступного объёма. Не отправляйте один запрос много раз подряд. Остановитесь, проверьте доступ в своём аккаунте и выберите запасной вариант.

Если все сервисы недоступны, преподаватель даст готовый пример изменений. Сравните старый и новый код, проверьте действие на сайте и объясните результат. В отчёте укажите, какие действия с ИИ не удалось выполнить. Подключение ИИ и отправку на GitVerse завершите после восстановления доступа.

## Перед первой отправкой на GitVerse

На работе 02 создайте пустой репозиторий в своём аккаунте GitVerse, без README и начального коммита. Скопируйте его HTTPS-адрес. Попросите агента настроить `origin` на этот адрес и показать `git remote -v`. Проверьте, что указан ваш аккаунт. Затем в терминале выполните:

```bash
git switch main
git push -u origin main
```

`origin` означает адрес вашей копии в интернете. Эти команды отправят исходную основную ветку в свою копию. После этого можно получать её обновления и отправлять рабочие ветки. В чужой общий стартовый проект изменения не отправляйте.

## Как показывать результат

На первой работе покажите сайт, свой вопрос и уточнение агенту, проверенные факты и сохранённый отчёт. Начиная со второй работы:

1. Сохраните прежний отчёт и обновите только документы текущей работы по TASK.md. При переходе ко второй работе добавьте файл автоматической проверки и два шаблона по её инструкции.
2. Создайте ветку с именем из задания. Поставьте задачу агенту, обсудите план и выполните изменение. Сами проверьте сценарий на сайте; тесты может запустить агент.
3. В VS Code откройте Source Control, раздел с изменёнными файлами. Нажмите на файл, чтобы увидеть старый и новый текст рядом. Такое сравнение называется diff.
4. По командам задания сохраните изменения в коммите и отправьте свою ветку на GitVerse.
5. На GitVerse откройте Merge Request, запрос на слияние. Это отправка изменений на проверку перед добавлением в основную версию проекта.
6. Дождитесь автоматических проверок на GitVerse. Они часто называются CI. Разберите замечания преподавателя и после принятия объедините изменения с main.

Пароли, ключи, файлы .env и реальные данные студентов в историю проекта не добавляйте. Для заданий используем только учебные заявки.
