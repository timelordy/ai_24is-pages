# 04. Проверить SQLite после перезапуска

**Цель:** На готовой основе доказать сохранение заявки после настоящей остановки и запуска сервера с тем же файлом SQLite.

**Рабочая ветка основного пути:** прежняя `feature/ticket-api` из 03.

## Продолжение 03 на готовой основе

Основной путь: прежняя папка, свой форк и проверенная интеграция 03. Ради перезапуска новую ветку не создавай.

`feature/persistence-workflow` относится к полному этапу: при отдельной дополнительной правке создавай её только из чистой принятой версии с поиском и основой. На `main` без этой версии не переключайся.

**Foundation**, готовая основа, содержит полностью работающий накопительный `after-04`. В нём уже есть обмен браузера с сервером через API, SQLite через встроенный `node:sqlite`, начальная загрузка 12 заявок и тесты. Ты не пишешь сервер и хранение с нуля, а проверяешь их работу в своей папке.

Справочная `_teacher-reference/foundation` остаётся образцом только для чтения: запускай свою папку с интеграцией 03. **Смена состояний заявки и её история остаются необязательным дополнением.**

H3/foundation или H4/foundation передаёт преподаватель после разрешения. Плановые закрытые пути: `dist/handoffs/H3/foundation`, `dist/handoffs/H4/foundation`; это не публичная автоматическая выдача. Пакет уже добавлен выборочно в 03, второй раз заменять папку не нужно. Recovery разрешён в новой папке с сохранением старой и отметкой восстановления; он не закрывает пропущенную работу.

## Что именно проверяет перезапуск

Заявка «Не работает проектор в 305» видна в браузере как карточка. Код страницы получает её запросом, сообщением серверу, и показывает поля из ответа.

- **API** задаёт согласованные способы общения этих программ.
- **Сервер** здесь работающая программа Node.js, запущенная на твоём компьютере. Это не обязательно удалённый компьютер.
- **HTTP** задаёт правила запросов и ответов.
- **Endpoint** это точка обращения: метод `GET` означает чтение и вместе с путём `/api/tickets` задаёт обращение за списком.
- **JSON** это структурированный текст с именами полей и значениями, например `title` и «Не работает проектор в 305».

**Сама карточка не доказывает, что запись сохранена на диске.**

- **Процесс** это работающая программа. Его память временная: если бы новая заявка хранилась только в ней, завершение сервера потеряло бы запись.
- **База данных (БД)** здесь файл SQLite с записями и их полями на диске.
- **SQLite** открывает этот файл из программы сервера; отдельный сервер базы данных не нужен.

Когда браузер закрывается или сервер останавливается, файл остаётся. Новая программа должна открыть **тот же файл** и вернуть прежние данные.

- **F5 в браузере** обновляет страницу. Браузер снова запрашивает данные, а программа сервера продолжает работать.
- **Ctrl+C в терминале сервера** завершает программу Node.js. Следующий `npm.cmd start` запускает новую программу. Именно это проверяет сохранение после остановки.

- **ID** это постоянный номер одной заявки, а не количество видимых карточек. Например, ID `113` не означает 113 записей: после первого создания на чистой базе их 13.
- **«Показано»** зависит также от поиска.

Для сравнения сохрани фактический ID и поля своей заявки.

- **Исходники** `server.mjs` и `backend/*.mjs` содержат инструкции для программы.
- **Данные** `.db` содержат заявки.

Создание заявки меняет базу, не требует дописывать её в `src/data.js` и не требует коммита. Git хранит версии кода, а не заменяет базу.

**Не редактируй `.db` как текст, не удаляй файл и записи ради нужного числа.**

Пошаговые действия и снимки находятся в [guide.json](guide.json). В этом задании основной результат получают проверкой, без новой правки кода.

## Как выбрать тот же файл

**Переменная окружения (environment variable)** `SERVICEDESK_DB` это именованная настройка терминала. PowerShell задаёт её записью `$env:SERVICEDESK_DB = ...`, а сервер при запуске читает значение как путь к базе.

- Настройка не создаёт заявку и сама не запускает сервер.
- Она остаётся в том же окне после **Ctrl+C**, но в новом терминале её нужно задать снова.
- Изменение настройки **не переключает уже работающий сервер** на другой файл.

Путь зависит от папки запуска:

- Папка в примере: `C:\Users\Анвар\Campus-ServiceDesk`.
- Имя файла: `stage03-04-check.db`.
- Полный путь: `C:\Users\Анвар\Campus-ServiceDesk\stage03-04-check.db`.

Используй фактическую папку из строки своего PowerShell и заметку 03, а не копируй путь примера. Сервер выводит адрес сайта, но не печатает выбранный путь базы: сверяй команду перед запуском в его терминале.

Если путь потерян, восстанови его с преподавателем по команде запуска и коду выбора базы **до проверки**.

## Разбор хранения

1. В OpenCode клавишей **Tab** выбери **Plan**, режим чтения без правок.
2. Если TASK 04 отсутствует в рабочей папке, вставь его текст перед запросом ниже: агент не видит страницу урока автоматически.
3. Добавь фактические ID и путь базы из своей заметки. Агент читает только рабочую папку.
4. Затем открой названные места сам в VS Code; **Ctrl+F** ищет текст в открытом файле.

Открой места хранения:

- В `server.mjs` найди `createSqliteStore`: путь выбирается из `process.env.SERVICEDESK_DB`, а без настройки используется `servicedesk.db` в папке запуска.
- `backend/sqlite-store.mjs` только передаёт функции из `backend/sqlite-core.mjs`.
- В `backend/sqlite-core.mjs` вызов `new DatabaseSync(filePath)` открывает файл.
- Функция `initialize` выполняет `SELECT COUNT(*) AS n FROM tickets`, подсчёт записей в таблице заявок. Исходные 12 записей из `src/data.js` добавляются **только при пустой таблице**. Это начальное заполнение иногда называют **seed**.
- В `create` вызов `insertTicket.run` добавляет проверенную заявку и получает её ID из базы.

Проследи путь от `POST /api/tickets`, запроса создания из 03, до этой записи. Попроси показать также `tests/sqlite.test.mjs`, тест повторного открытия базы. Он полезен, но **не заменяет остановку программы**.

Проверка перезапуска использует тот же файл без удаления данных. Сервер и хранение уже готовы; написание их с нуля, workflow и история не входят в эту задачу.

## Проверь среду и файл

Чтобы проверить доступность SQLite, не останавливая сайт раньше времени, в VS Code выбери «Терминал → Создать терминал». В новом терминале своей папки выполни команды по одной:

```powershell
node --version
node -e "import('node:sqlite').then(() => console.log('sqlite available'))"
```

Нужен **Node >=22.13.0** для запуска без дополнительных флагов. При ошибке импорта обновление согласуй с преподавателем. Предупреждение ExperimentalWarning само по себе не означает провал тестов. Отдельный сервер БД или npm-пакет SQLite не нужен.

Если продолжаешь позже, но интеграция 03 уже проверена, запусти сервер с записанным прежним файлом, затем зафиксируй ID, поля и число записей до остановки. Если заявки для сравнения ещё нет, сначала создай её по шагу 4 руководства 03 и запиши ID и поля. Только для отдельной проверки на новом файле выбери свободное имя без удаления прежних данных:

```powershell
$env:SERVICEDESK_DB = 'stage03-04-check.db'
npm.cmd start
```

Если файл уже содержит твои записи, не удаляй его ради 12. Для проверки чистого seed выбери другой файл. На чистом файле 12 уникальных ID 101..112; первая новая запись 113. В рабочей БД используй фактические ID и число записей.

После создания запомни ID, `title` и остальные поля.

1. Выбери терминал, в котором работает сайт, нажми **Ctrl+C**.
2. Если появилось подтверждение завершения, подтверди его.
3. Дождись строки ввода PowerShell с путём и знаком `>`. Если строки ввода нет, проверь выбранный терминал; новый сервер пока не запускай.

Затем **в том же терминале**:

```powershell
npm.cmd start
```

В новом терминале сначала задай `$env:SERVICEDESK_DB = 'полный путь из твоей записи'`, подставив свой путь вместо текста примера. Если относительное имя и папка запуска изменятся, можно случайно открыть другую базу.

Дождись адреса из вывода сервера. Обычно это `http://127.0.0.1:4173`:

- `127.0.0.1` означает свой компьютер;
- `localhost` тоже имя своего компьютера;
- `4173` это порт программы.

При другом порте используй **фактический адрес**.

1. Открой этот адрес в браузере, обнови страницу **F5** и найди заявку по заголовку (`title`), сверь ID и поля.
2. В новой вкладке открой, например, `http://127.0.0.1:4173/api/tickets/113`, подставив свой порт и ID. Адрес вводят в строку браузера и нажимают **Enter**: это `GET` за одной записью. Ты увидишь её JSON вместо карточки.
3. Открой на том же адресе `/api/tickets` и проверь отсутствие повторных исходных записей.

Сверь список до и после остановки:

- каждый исходный ID `101..112` должен встретиться **один раз**;
- общее число записей должно совпасть;
- **сам перезапуск ничего не создаёт**.

На исходных фикстурах тест поиска по-прежнему проверяет:

- пусто → 12;
- `ПРОЕКТОР` / `305` / пробелы → `[101]`;
- `марсианский` → 0;
- очистка → 12.

От рабочей БД после новых созданий число 12 не требуют. **Не удаляй записи, чтобы подогнать проверку.**

Если карточки нет, очисти поиск и проверь `GET` по прежнему ID. Если API отвечает `not_found` или возвращает только исходные 12 записей, сверь:

- адрес сервера;
- папку запуска;
- путь базы.

Значение переменной в новом терминале не доказывает, с каким файлом работал прежний процесс: опирайся на заметку и команду запуска. Не создавай замену заявки и не удаляй файлы.

Передай агенту ожидание, факт и команду запуска. После согласованного исправления повтори настоящий перезапуск с прежним файлом.

Если адрес не появился, сначала прочитай ошибку. При `EADDRINUSE` проверь свои терминалы на оставшийся сервер; неизвестный процесс не завершай. При ошибке открытия базы сверь путь и его папку с преподавателем, не удаляя файл и не меняя имя ради запуска.

## Необязательные статусы и история

**Дополнение не требуется для высокой итоговой оценки и перехода к 06.** Состояния заявки:

- `new` (**«Новая»**);
- `in_progress` (**«В работе»**);
- `resolved` (**«Решена»**);
- `closed` (**«Закрыта»**).

API меняет состояние запросом `PATCH`, методом изменения существующей записи, по адресу `/api/tickets/ID/status`. В теле JSON передаётся, например, `{"status":"in_progress"}`.

Если выбрал дополнение с преподавателем, попроси помощника работать с одной учебной заявкой и её фактическим ID без правок кода:

1. Проверь переход новой заявки сразу в `closed`: ответ `409` означает конфликт с правилами, состояние должно остаться `new`.
2. Последовательно проверь `new → in_progress → resolved → closed`, читая ответ после каждого запроса.

При запрете запросов остановись для ручной проверки преподавателем; не меняй разрешения. Это изменения данных выбранной заявки.

История хранит события заявки. В браузере открой `/api/tickets/ID/history` на адресе своего сервера: замени `ID` её номером.

- `created` означает создание;
- `status_changed` означает смену состояния.

Сравни события с выполненными переходами. Подробные действия и пример надписи **«В работе»** находятся в шаге 4 guide.

## Сохранение и происхождение

**Diff** это сравнение старых и новых строк: так можно отличить перенос готовой основы от собственной строки курсора.

- Сверь `git status --short`, `git diff` и новые файлы.
- Обычный `git diff` не показывает новые файлы и уже выбранные для коммита правки: новые открой отдельно, выбранные посмотри через `git diff --cached`.
- Интеграция сохранена в конце 03; если код не менялся, рабочий diff может быть пустым. Посмотри правку в истории коммита 03; отдельный коммит для перезапуска не нужен.

Если пришлось исправить исходники, выбери только проверенные файлы в **«Управлении версиями»**, прочитай `git diff --cached` и сохрани исправление локальным коммитом. **Не выбирай** БД `.db`, `.db-wal`, `.db-shm`, `_teacher-reference/`, `.env` и ключи.

Сохрани известные SHA и версию foundation. Продолжай эту папку и свой форк; **05 необязателен**. `REPORT`, Issue, MR, CI и слияние в `main` не требуются.

## Успешный результат

- Запись с тем же ID и полями найдена после Ctrl+C и нового запуска Node с тем же файлом SQLite.
- Исходные заявки повторно не добавились, собственный поиск сохранился.
- Известны полный путь БД, SHA проверенной версии и версия основы. В фактическом выводе тестов нет ошибок; сервер и SQLite честно отмечены как полученные готовыми.
- Необязательные workflow/история явно отмечены как выбранные или пропущенные.

## Не засчитывается, если

- Показано только обновление страницы без остановки Node.
- После нового запуска запись исчезла или получила другие поля.
- Каждый запуск повторно добавляет исходные записи.
- Вместо проверки своей интеграции показан чужой пример без объяснения происхождения.
