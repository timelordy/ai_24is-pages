# 03. Агент вносит ограниченную правку: фильтр по статусу

**Цель:** Пройти настоящий цикл изменения и проверить результат независимо от сообщения агента.

**Рабочая ветка:** `feature/status-filter`

## Требование

Добавить фильтр со значениями `Все`, `Открытые`, `Закрытые`.

## Контракт функции

Создайте и экспортируйте:

```js
filterTicketsByStatus(tickets, status)
```

- `all` возвращает копию всех заявок;
- `open` и `closed` фильтруют;
- неизвестный статус вызывает `RangeError`;
- исходный массив и объекты не изменяются.

## Задание

1. До запуска агента запишите ожидаемые ID: `all → [1,2,3,4,5,6]`, `open → [1,3,4,6]`, `closed → [2,5]`.
2. Попросите агента дать короткий план и сравните его с планом прошлой пары.
3. Разрешите изменить только `index.html`, `src/app.js`, `src/tickets.js` и `tests/filter.test.mjs`. Другой файл можно менять только после явного объяснения зачем.
4. Просмотрите `git diff` до запуска тестов. Отклоните переписывание проекта и новые зависимости.
5. Запустите `npm test`.
6. Запустите приложение и вручную проверьте три режима фильтра и счётчик показанных заявок.
7. Сделайте commit, push и дождитесь GitVerse CI.
8. В `REPORT.md` вставьте вывод тестов, ссылку на CI и объясните `filterTicketsByStatus` своими словами.

## Успешный результат

- `npm test` завершается с кодом `0`; после реализации проходят **10 тестов**: 5 базовых + 5 тестов фильтра;
- `filterTicketsByStatus(tickets, "all").map(x => x.id)` даёт `[1,2,3,4,5,6]`;
- `open` даёт `[1,3,4,6]`, `closed` даёт `[2,5]`;
- значение `later` вызывает `RangeError`;
- тест подтверждает, что исходный `tickets` не изменился;
- в UI режимы показывают соответственно **6 / 4 / 2** заявки, а счётчик совпадает с количеством карточек;
- в консоли браузера нет ошибок;
- GitVerse CI зелёный на commit, который студент показывает преподавателю;
- `package.json` не получил новых dependencies.

## Не засчитывается, если

- фильтр визуально «похож на работающий», но точные ID или количество не совпадают;
- студент показывает сообщение GigaCode «тесты прошли» вместо реального вывода `npm test`/CI;
- изменены тесты так, чтобы принять неправильное поведение;
- агент добавил библиотеку или переписал приложение без необходимости;
- студент не может объяснить, почему `all` должен возвращать новый массив.

## Что сдавать

- commit и ссылка на зелёный GitVerse CI;
- `REPORT.md` с выводом 10 тестов;
- таблица ручной проверки `all=6`, `open=4`, `closed=2`;
- краткое объяснение diff и функции фильтра.

## Индивидуальный вопрос

Что возвращает функция для `all`, и почему результат не должен быть тем же массивом по ссылке?

## Что принимает преподаватель

- точные ID для трёх режимов совпадают с контрактом
- неизвестный статус даёт `RangeError`, вход не мутируется
- UI показывает 6 / 4 / 2 и консоль чистая
- локальные тесты и CI зелёные
