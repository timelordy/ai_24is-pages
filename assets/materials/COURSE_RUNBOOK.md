# Регламент курса GitVerse + GigaCode

## Главный принцип

Одна новая способность агента на пару и один проверяемый артефакт в GitVerse. Настройка выполняется вместе со студентами, но преподаватель заранее проверяет один одинаковый маршрут на реальном ПК аудитории.

## Ритм обычной пары

| Минуты | Действие |
|---|---|
| 0–10 | Что сегодня должно появиться в репозитории |
| 10–25 | Демонстрация одного цикла преподавателем |
| 25–65 | Работа в персональных форках |
| 65–80 | Тесты, diff, commit/MR и разбор ошибки |
| 80–90 | Индивидуальный вопрос и фиксация результата |

На первой паре установка может занять больше времени. Жёсткая граница: после 35-й минуты не чинить один ПК всей группой. Студент пересаживается или работает в паре со сменой ролей, а проблема записывается в пилот.

## Основной и резервный маршруты

**Основной:** GitVerse Lab → локальный VS Code + GigaCode → GitVerse CI/CD.

**При наличии доступа:** GigaCode Session Plan/Build, `/init`, `/review`, skills.

**Резерв:** заранее подготовленный учебный ПК или работа в паре. Текстовая демонстрация преподавателя не засчитывается как личный агентный прогон.

## Правила сложности

- одно функциональное изменение за пару;
- максимум два исходных файла без отдельного согласования;
- никаких новых библиотек в базовом маршруте;
- проект не переписывается на фреймворк;
- студент сначала записывает ожидаемое поведение;
- агентный ответ проверяется тестом или сценарием;
- `AGENTS.md` содержит только специфичные для проекта правила;
- skills описывают повторяемую процедуру, а не заменяют понимание.

## Приём

Пары 1–6 принимаются по артефактам GitVerse и короткому вопросу. Финал проводится индивидуально. Если в подгруппе больше 16 студентов, часть индивидуальных проверок переносится на шестую пару: 50 минут защиты не расширяются силой административного оптимизма.

## До запуска

1. Провести пилот на трёх студентах разной подготовки и одном учебном ПК.
2. Проверить регистрацию, GigaCode, clone/push, Node.js и GitVerse CI.
3. Уточнить, кому доступны Sessions, GigaCode-разработчик и MCP.
4. Создать семь шаблонных репозиториев из `dist/gitverse-repos`.
5. Создать модуль и задания в GitVerse Lab.
6. Включить задачи, CI/CD и защиту основной ветки.
7. Не включать автоматический платный перерасход облачной среды без отдельного решения кафедры.
