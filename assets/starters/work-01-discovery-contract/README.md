# 1. Первый разговор с агентом в своём проекте

**Цель:** Запустим готовый сайт, попросим ИИ разобраться в его файлах и проверим ответы на экране.

Ветка в Git, именованная линия истории проекта, позволит отдельно сохранить свою работу. В инструкции используем `stage/01-discovery`. Вторую папку создавать не нужно. Имя ветки не является критерием отчёта.

На сайте курса есть иллюстрации, снимки программ и схемы с переключением. Здесь те же действия текстом. Пройди подготовку, задай агенту вопрос, сам проверь ответ и коротко опиши результат. Предварительный опыт с терминалом и Git не требуется.

## Часть 1. Познакомься с GitVerse

**Где работаем:** В браузере

Campus ServiceDesk, наш учебный сайт, показывает **12 заявок** о неполадках в кампусе. Например, заявка №101 сообщает о проекторе в аудитории 305.

Файлы сайта содержат данные и инструкции для программы. Список файлов ещё не работающий сайт: позже запустим программу и увидим заявки в браузере.

Сейчас откроем GitVerse, российскую площадку СберТеха, где преподаватель разместил проект.

- **Git** сохраняет историю изменений проекта на компьютере.
- **GitVerse** хранит проект в интернете, чтобы его можно было скачать и передать преподавателю.

Git можно использовать без аккаунта GitVerse. Для курса выбрана площадка, где уже лежит проект преподавателя.

- **Репозиторий** состоит из файлов проекта и истории их изменений в Git. На GitVerse откроем репозиторий преподавателя.
- **Ветка** означает именованную линию истории проекта. Над файлами увидишь `main`: так названа основная ветка.

Подробнее разберём ветки перед их созданием в части 9.

## Часть 3. Установи VS Code

**Где работаем:** В браузере и VS Code

VS Code, редактор файлов, позволит читать и менять проект. Внутри его окна откроем терминал: панель, где вводят точные команды для программ и получают текстовый ответ.

- **Редактор** открывает файлы.
- **Терминал** запускает программы. Позже внутри него откроется OpenCode со своим полем для поручений ИИ; помощник сможет читать файлы и запускать команды.
- **Сервер**, отдельная работающая программа, передаст страницу браузеру.
- **Браузер** покажет результат пользователю; он сам файлы проекта не редактирует.

### 1. Скачай редактор

Открой [страницу VS Code](https://code.visualstudio.com/Download), выбери **Windows** и **User Installer x64**. Установи и запусти программу.

**Проверь у себя:** Открылось окно Visual Studio Code.

### 2. Найди место для команд

В верхнем меню выбери **«Терминал → Создать терминал»** (Terminal → New Terminal).

Внизу откроется панель со строкой текста и мигающим курсором. Щёлкни рядом с курсором: сюда будем вводить команды.

**Проверь у себя:** Внизу VS Code открыта панель терминала и виден курсор.

**Подсказка:** `PS`, путь к папке и знак `>` уже написаны программой. Копировать их не нужно. Вводи только команду из инструкции.

### 3. Проверь Git в терминале

Введи команду ниже в терминале и нажми Enter.

- `git` обращается к установленной программе.
- `--version` просит напечатать её версию.

Пробел между ними нужен; объяснение команды вводить не нужно.

**Введи в терминал VS Code:**

```text
git --version
```

**Пример ответа после `git --version` (вводить не нужно):**

```text
git version 2.54.0.windows.1
```

**Проверь у себя:** Под введённой командой появилась строка git version и номер. Номер может отличаться от снимка.

**Подсказка:** Текст под командой показывает её результат. Его повторно вводить не нужно. Если Git не найден, закрой VS Code, открой снова и повтори только эту проверку.

**Результат шага:** VS Code открыт, ты знаешь, где его терминал.

## Часть 4. Установи Node.js

**Где работаем:** В браузере и терминале VS Code

Файлы сайта уже написаны, но их ещё нужно запустить. Для этого установим Node.js. Это программа, которая выполняет код JavaScript на компьютере. Такую программу называют средой выполнения.

**Что будет после установки:** Появится команда `node`: с её помощью помощник запустит `server.mjs`. Эта программа передаст страницу с заявками в браузер.

Вместе с Node.js установится npm, через него на следующем шаге установим OpenCode.

### 1. Выбери установщик для Windows

Открой [страницу Node.js](https://nodejs.org/en/download). Выбери параметры:

- **LTS**, выпуск с длительной поддержкой, версии **22.13.0 или новее**.
- Для Windows на обычном компьютере: **x64** и **Windows Installer (.msi)**, готовый установщик.

Если у компьютера ARM-процессор, уточни вариант у преподавателя.

Скачай файл и установи программу. Затем закрой и снова открой VS Code.

**Проверь у себя:** Установка завершена, VS Code открыт заново.

**Подсказка:** На снимке показан именно блок для Windows. Команды Docker в верхней части страницы пропусти.

### 2. Проверь Node.js и npm

Открой **«Терминал → Создать терминал»**. Вводи строки по одной, после каждой нажимай Enter и жди ответа.

- `node --version` проверяет версию Node.js.
- `npm.cmd --version` проверяет npm, программу для установки пакетов и запуска команд проекта. Она устанавливается вместе с Node.js.

Суффикс `.cmd` выбирает команду Windows и помогает избежать запрета PowerShell на запуск `npm.ps1`.

**Введи в терминал VS Code:**

```text
node --version
npm.cmd --version
```

**Пример ответа после `node --version` (вводить не нужно):**

```text
v24.15.0
```

**Пример ответа после `npm.cmd --version` (вводить не нужно):**

```text
11.12.1
```

**Проверь у себя:** После node --version появился номер с буквой v, после npm.cmd --version ещё один номер. Если вместо номера показана ошибка, установку пока нельзя считать проверенной.

**Результат шага:** Компьютер готов запускать учебный сайт.

## Часть 5. Установи помощника OpenCode

**Где работаем:** В терминале VS Code

OpenCode, локальная программа на твоём компьютере, принимает поручения в папке проекта. Подключённая модель ИИ составляет ответы и выбирает действия, а OpenCode выполняет их через инструменты: чтение файла, его изменение или запуск команды. Помощника с такими инструментами называют агентом.

Установка OpenCode ещё не подключает модель. В части 8 настроим Inception, провайдера, то есть сервис компании, который выполняет модель на своих серверах. Mercury 3 (в списке Mercury3) будет выбранной моделью. Сейчас установим только программу OpenCode.

Модель отвечает за текст и решения, инструменты OpenCode работают с файлами и командами. Режим задаёт работу с инструментами:

- **Plan** («планирование»): читаем и обсуждаем план.
- **Build** («выполнение»): разрешаем согласованные изменения и запуск.

Переключать их будем перед первым поручением. OpenCode может отдельно запросить разрешение конкретного инструмента; перед подтверждением прочитай предложенное действие.

### 1. Установи OpenCode и проверь результат

Для скачивания программы нужен интернет. В обычном терминале VS Code введи первую команду и нажми Enter. Дождись возвращения строки с курсором, затем второй командой проверь версию.

npm устанавливает пакеты, готовые наборы файлов программ:

- `npm.cmd install` устанавливает пакет `opencode-ai`.
- `-g` делает команду OpenCode доступной из разных папок.

**Нужен OpenCode V1**; пакет `@opencode/cli` относится к другой версии, его рядом не устанавливай.

**Введи в терминал VS Code:**

```text
npm.cmd install -g opencode-ai
opencode.cmd --version
```

**Пример ответа после `opencode.cmd --version` (вводить не нужно):**

```text
1.19.3
```

**Проверь у себя:** После второй команды появился номер версии OpenCode. Это подтверждает установку; подключение ИИ проверим позже.

**Подсказка:** Если компьютер пишет, что команда не найдена, закрой и снова открой VS Code, затем повтори проверку. Саму установку без причины повторять не нужно.

**Результат шага:** OpenCode установлен. Сам разговор с ИИ начнём после открытия папки проекта.

## Часть 8. Подключи ИИ к OpenCode

**Где работаем:** В браузере и внутри OpenCode

Сначала добавим настройки проекта, затем подключим ИИ. До входа в кабинет разберём, что подключаем:

- **OpenCode** работает на твоём компьютере. Это программа для общения с ИИ и работы с инструментами.
- **Inception** выполняет модель на своих серверах. Такой сервис компании называют провайдером.
- **Mercury 3** (Mercury3 в списке) отвечает на вопросы и помогает с кодом. По назначению она похожа на модели, с которыми общаются в ChatGPT или Claude, но это другая модель.

Например, в OpenCode можно спросить: «Где хранятся заявки?» Модель поможет найти ответ по файлам проекта, которые прочитает агент.

Путь запроса:

1. Ты пишешь в OpenCode.
2. OpenCode отправляет запрос через интернет провайдеру Inception.
3. Модель Mercury 3 обрабатывает запрос.
4. Ответ возвращается в OpenCode.

Для этой работы модели нужен интернет.

Прочитанные агентом файлы могут попасть в запрос как **контекст**, сведения для ответа. Вся открытая папка автоматически не отправляется. Работай с учебными несекретными данными, без паролей и реальных персональных данных.

Google здесь нужен лишь для входа в кабинет Inception. Для доступа программы создадим отдельный **API-ключ**, секретную строку доступа от твоего аккаунта.

API означает способ общения программ. Ключ не является паролем Google; API самого учебного сайта сейчас не создаём.

Доступность сервиса и условия использования могут меняться. Перед подключением прочитай их в кабинете.

**Покупать тариф или пополнять баланс не требуется**: при ограничении выбери запасное подключение с преподавателем.

**Для чего нужен набор подготовки:** В скачанном проекте остались инструкции для прежнего помощника. Набор обновит `README.md` и `TASK.md`, добавит `opencode.json` и предложит необязательный шаблон `REPORT.md`.

Свои заметки заменять не нужно. Файлы самого сайта и папка `.git` останутся на месте.

Выбор `/models` меняет модель, а Tab переключает режим **Plan/Build**; это разные настройки.

### 1. Добавь актуальные файлы для этой работы

Скачай набор и распакуй ZIP, сжатый архив файлов, через **«Извлечь всё»** в Проводнике. Помести три файла прямо в `Campus-ServiceDesk` рядом с `package.json`, **без дополнительной вложенной папки**:

- `opencode.json` содержит настройки без ключей.
- `README.md` объясняет начало работы.
- `TASK.md` содержит задание.

`REPORT.md`, необязательный шаблон заметки, копируй, только если своих записей ещё нет. Остальные файлы и `.git`, папку истории Git, не удаляй.

Скачай набор opencode-setup.zip на сайте курса.

**Проверь у себя:** В корне Campus-ServiceDesk есть opencode.json и актуальная инструкция TASK.md. Если у тебя уже были заметки, они сохранились.

### 2. Войди в Inception через Google

Кабинет Inception нужен, чтобы получить ключ для OpenCode. Открой его по ссылке и нажми **Continue with Google** («Продолжить с Google»). В окне Google выбери свой аккаунт; если вход ещё не выполнен, войди обычным способом.

## Часть 9. Разберись с версиями и создай ветку

**Где работаем:** В поле сообщения OpenCode

Git хранит версии проекта:

- **Коммит** (commit) записывает снимок выбранного состояния с подписью.
- **Ветка** (branch) даёт имя линии таких записей: `main` хранит исходную версию, а `stage/01-discovery` позволит продолжить её отдельно, в той же папке.

Сначала попросим агента показать состояние, затем сохранить подготовку и выбрать рабочую ветку. **В этой работе приложение не меняем.**

В части 13 коротко опишем проверенный результат; `REPORT.md` лишь необязательная заготовка.

- **Сохранение файла** через Ctrl+S записывает текущий текст на диск.
- **Подготовка, staging** выбирает изменения для следующего снимка. В VS Code это кнопка **+** возле файла.
- **Коммит** сохраняет снимок подготовленного состояния проекта в истории Git с подписью, чтобы позднее сравнить версии. В снимке остаётся и прежнее содержимое отслеживаемых файлов без изменений.
- **Отправка, push** передаёт коммиты в интернет. Сам коммит ничего не отправляет; push изучим во второй работе.

Например, если изменить `README.md` и `REPORT.md`, но подготовить только `README.md`, коммит запишет новую версию `README.md`. Правка `REPORT.md` останется на диске вне коммита.

Ветка, именованная линия истории проекта, позволяет продолжить исходную версию отдельно. `main` содержит исходный сайт и подготовку. От неё создадим `stage/01-discovery`.

Сначала обе ветки указывают на один коммит; новая папка и новые изменения от этого не появляются. Если потом записать заметку коммитом в `stage/01-discovery`, эта ветка продолжится, а `main` останется на прежней записи.

У каждого коммита есть **SHA**, уникальный идентификатор из букв и цифр.

### 1. Посмотри, что уже хранится в Git

Для проверки без правок выберем **Plan** («планирование»). В OpenCode нажимай Tab, пока это слово не появится возле поля сообщения. Вставь туда запрос ниже и нажми Enter.

**Отправь агенту в OpenCode:**


Расскажи своими словами, какую задачу решал с агентом, что получилось и как ты это проверил. **Форма и объём свободные.**

Можно написать самому или попросить агента помочь. Ниже показан удобный вариант с `REPORT.md`; другой способ сохранить заметку тоже подходит.

`REPORT.md`, необязательная заготовка заметки, содержит обычный текст. Расширение `.md` означает Markdown: текст с обозначениями заголовков и списков.

Открыв такой файл в VS Code, нажми Ctrl+Shift+V, чтобы увидеть оформление. Можно выбрать другой формат.

Версии программ, выводы команд и заданное число вопросов в отчёт добавлять не требуется.

### 1. Напиши заметку сам или попроси агента помочь

Если хочешь поручить текст помощнику, выбери **Build** и отправь пример запроса ниже. Разрешай изменение **только файла своей заметки**.

Если пишешь сам или уже сохранил описание другим способом, переходи к проверке текста.

**Отправь агенту в OpenCode:**

```text
Помоги коротко описать мою работу в REPORT.md: какую задачу я решал с тобой, что получилось и как я сам это проверил.
Опирайся только на наш разговор. Не добавляй действий, которых не было, и не заполняй отчёт по обязательной форме. Если чего-то не знаешь, спроси меня.
Сохрани уже записанные мной выводы. Не меняй приложение, настройки и тесты.
```

**Проверь у себя:** В заметке описан твой опыт. Можно обойтись несколькими предложениями; обязательного списка разделов нет.

### 2. Проверь, что заметка соответствует твоей работе

Прочитай написанное. Можешь ли ты показать описанный результат и объяснить свою проверку?

Если агент добавил лишнее или приписал невыполненные действия, поправь текст сам или попроси его. Ниже пример такого запроса.

**Отправь агенту в OpenCode:**

```text
Сверь заметку с нашим разговором. Покажи, что в ней основано на моих действиях и проверках, а что осталось неподтверждённым.
Не придумывай недостающие проверки и не меняй файлы без моего решения.
```

**Проверь у себя:** В заметке остались только те действия, результаты и трудности, которые были на самом деле.

**Подсказка:** Не нужно специально искать ошибку в хорошем ответе или делать дополнительное уточнение ради отчёта. Если что-то не получилось, можно честно описать это.

### 3. Сохрани заметку удобным способом

Если используешь `REPORT.md`, сохрани файл.

Для практики можно попросить агента сохранить его версию в Git запросом ниже. Это необязательный способ хранения: точное имя ветки, подпись коммита и число команд не являются требованиями к отчёту.

**Отправь агенту в OpenCode:**

```text
Покажи изменения моей заметки в REPORT.md и подготовь её сохранение в Git. Не включай другие файлы. Дождись моего отдельного подтверждения. Предложи понятную подпись сохранения; точная формулировка не важна.
```

**Проверь у себя:** Заметка сохранена выбранным тобой способом. Для показа готовы результат работы и объяснение того, как ты его проверил.

**Результат шага:** У тебя есть короткое описание своей работы и результат, который ты можешь показать и объяснить.

## Что показать преподавателю

- Покажи результат своей работы с агентом: например, открытый сайт, выбранную заявку или найденное место в файле.
- Коротко объясни, что хотел выяснить, как помог агент и что ты проверил сам. Запросы, ход работы и решения могут различаться.
- Покажи свою краткую заметку в удобном формате. REPORT.md подходит как один из вариантов; обязательной формы, объёма и числа выводов нет.

## Объясни своими словами

- Что ты хотел получить и что получилось?
- Как ты проверил результат?
- Что осталось непонятным, если такое было?

## Успешный результат

- Ты работал с агентом, сам проверил полученный результат и можешь его показать и объяснить. Короткая заметка описывает именно твою работу. Запросы, способы проверки и решения могут различаться.

REPORT.md служит необязательным шаблоном. Объём, оформление, версии программ, вывод команд, число утверждений и уточнений, найденная ошибка, имя ветки и подпись коммита не оцениваются. Не нужно выполнять дополнительные действия ради заполнения формы.

## Не засчитывается, если

- Есть только скопированный ответ без самостоятельной проверки и объяснения либо в заметке описаны выдуманные действия. Незавершённый результат и трудности можно обсуждать с преподавателем: важна проделанная работа, а не одинаковый итог у всех.

## Что принимает преподаватель

- Показ результата, короткое объяснение самостоятельной проверки и заметку в удобной форме. Можно писать самому или с помощью агента; студент отвечает за содержание. Git изучаем в маршруте, но конкретный способ сохранения заметки не определяет оценку.

## Если помощник не подключается

Открой помощь в разделе «Программы» на сайте курса. Сначала попробуй доступную бесплатную модель OpenCode Free через /models. Второй запасной вариант, сервис NVIDIA, подключай после проверки преподавателем. Если подключение недоступно, преподаватель даст готовый пример для разбора. Просто упомяни, с чем работал; отдельная форма описания сбоя не нужна.
