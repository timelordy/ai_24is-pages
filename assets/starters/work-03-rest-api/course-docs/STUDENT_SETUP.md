# Как подготовить рабочее место

Эта памятка лежит в папке учебного проекта. Подробные шаги смотри в TASK.md и на странице текущей работы курса.

Проект Campus ServiceDesk хранится в одной папке. В начале в нём есть 12 готовых заявок. На следующих занятиях будем дополнять этот проект.

## Какие программы используются

- В VS Code открывай файлы и работай с кодом.
- Git хранит историю изменений на компьютере. Зафиксированная версия называется коммитом, отдельная линия работы называется веткой.
- GitVerse хранит удалённую копию проекта. Туда ты отправляешь результат преподавателю.
- Node.js запускает учебный сайт и его тесты. Нужна версия 22 или новее.
- OpenCode помогает читать и менять файлы. Для ответов он подключается к Inception и модели Mercury.

## Сначала открой и запусти учебный сайт

1. Если программы ещё не установлены, открой первую работу на сайте курса и установи их по порядку.
2. В VS Code выберите «Файл → Открыть папку». Откройте папку, где находится package.json.
3. В меню выбери «Терминал → Создать терминал». Внизу появится поле для команд. Вводи команды по одной и нажимай Enter:

```text
npm test
npm run start
```

Первая команда запускает автоматические тесты кода. Попроси агента показать итог и объяснить ошибку, если тест завершился неудачно. Вторая команда запускает учебный сайт. Открой в браузере адрес из терминала и проверь, что видны 12 заявок.

Если PowerShell запрещает запуск npm.ps1, введи `npm.cmd test` и `npm.cmd run start` или выбери в VS Code терминал Command Prompt.

Если ты скачал ZIP, проверь, есть ли в папке история Git и ветка main. Если их нет, обратись к преподавателю: при подготовке проекта из ZIP важно не смешать его историю с историей форка.

## Основной маршрут: OpenCode + Inception

Этот раздел относится только к маршруту OpenCode + Inception. Если выбираешь Freebuff CLI, не выполняй настройку OpenCode и Inception: смотри [инструкцию Freebuff](https://timelordy.github.io/ai_24is-pages/#stack/freebuff). Freebuff запускается в терминале из той же папки проекта; он не использует `opencode.json`, а настройки разрешений OpenCode на него не распространяются.

1. В терминале VS Code установите OpenCode V1:

```text
npm.cmd install -g opencode-ai
opencode.cmd --version
```

Должен появиться номер версии. Для курса нужен пакет opencode-ai. Пакет V2 с названием @opencode/cli использует ту же команду; не устанавливай обе версии одновременно. Если увидишь другую версию, покажи результат преподавателю.

2. Проверь, что в папке проекта есть opencode.json. Это готовый файл настроек: в нём уже указаны Inception и Mercury 3. Перед записью файла или запуском команды помощник спрашивает разрешение.
3. Создай личный аккаунт Inception и ключ API по [официальной инструкции](https://docs.inceptionlabs.ai/get-started). Ключ даёт программе доступ к ИИ от твоего аккаунта. Храни его как пароль.
4. В терминале VS Code введи `opencode.cmd`. Откроется помощник. Теперь команды с косой чертой вводятся внутри него.
5. Введи `/connect`, выбери `Other`, укажи имя подключения `inception` и вставь личный ключ в поле подключения.
6. Введи `/models` и выбери `inception/mercury-3`. Слово provider в интерфейсе означает сервис, который предоставляет модель ИИ.
7. Внутри OpenCode нажимай Tab, пока не появится Plan. Попроси найти файл с заявками и назвать его путь. Затем открой файл сам и сверь ответ с содержимым.

В работе 01 задай свой вопрос о сайте и проверь ответ по файлу или экрану. При необходимости попроси уточнить ответ. Сохрани вывод в короткой заметке. Код приложения менять нельзя. В следующих работах сперва проверь план, затем клавишей Tab переключи OpenCode в Build и разрешай только нужные изменения файлов.

Не вставляй ключ в opencode.json, отчёт, код, сообщение преподавателю или скриншот. [Описание подключения OpenCode](https://opencode.ai/docs/providers/) и [переключение режимов](https://opencode.ai/docs/agents/).

Информация о бесплатных токенах в этой памятке зафиксирована на 26 октября 2026 года: Inception указывал 100 миллионов стартовых токенов новым аккаунтам. Токены измеряют объём текста. Проверь актуальные условия и остаток в личном кабинете. Доступ из учебной сети и работа для всей группы пока не проверены.

## Если помощник не отвечает

Сначала сохрани свои файлы. Внутри OpenCode команда `/models` открывает список моделей. Первый запасной вариант: доступная бесплатная модель OpenCode Free. Список и ограничения меняются.

Второй вариант после проверки преподавателем: сервис NVIDIA. Получи личный ключ, выбери NVIDIA через `/connect`, затем согласованную модель через `/models`. Снова проверь, что файл читается. [Сервисы, которые можно подключить](https://opencode.ai/docs/providers/).

Ошибка 429 означает ограничение запросов или доступного объёма. Не отправляйте один запрос много раз подряд. Остановитесь, проверьте доступ в своём аккаунте и выберите запасной вариант.

Если все сервисы недоступны, преподаватель даст готовый пример изменений. Сравните старый и новый код, проверьте действие на сайте и объясните результат. В отчёте укажите, какие действия с ИИ не удалось выполнить. Подключение ИИ и отправку на GitVerse завершите после восстановления доступа.

## Своя копия на втором занятии

В работе 02 открой [Campus-ServiceDesk преподавателя](https://gitverse.ru/ultra_turbo_killer/Campus-ServiceDesk), нажми «Форк» и создай копию в своём аккаунте. Fork создаёт удалённый репозиторий, Clone скачивает его на компьютер. Продолжай работу в прежней папке. Если её нет, клонируй форк через Git: Clone в VS Code.

Сохрани свою заметку. Перед сменой ветки проверь состояние проекта. Скопируй HTTPS-адрес своего форка и уточни у агента или преподавателя, как обновить `origin`. Затем проверь адреса для получения и отправки изменений:

```bash
git status
git remote -v
git remote get-url --push origin
```

`origin` должен вести в твой аккаунт. Эти команды ничего не отправляют. Если для проекта из ZIP запускали `git init`, не соединяй разные истории принудительно: сохрани папку и обратись к преподавателю. Можно отдельно клонировать свой форк и перенести заметку. Не отправляй изменения в исходный проект преподавателя.

## Как показывать результат

На первой работе покажите сайт, свой вопрос агенту, результат самостоятельной проверки и короткую заметку. На второй работе:

1. Сохраните прежние записи и откройте TASK занятия 02. Бланк REPORT необязателен.
2. Создайте ветку `feature/frontend-query`. Обсудите с агентом план и добавьте только поиск. Сами проверьте сценарий на сайте; тесты может запустить агент.
3. В VS Code откройте Source Control, раздел с изменёнными файлами. Нажмите на файл, чтобы увидеть старый и новый текст рядом. Такое сравнение называется diff.
4. По командам задания сохраните изменения в коммите и отправьте свою ветку на GitVerse.
5. Откройте коммит в своей ветке GitVerse и сверьте его SHA с локальным HEAD. Покажите поиск и объясните одно решение. Если сеть недоступна, покажите локальный результат и явно укажите, что отправка ещё не выполнена.

На второе занятие планируем 60 минут работы и 30 минут резерва на затруднения. Фильтры, сортировка, Issue, Merge Request и CI не обязательны. Работу 03 начинайте от принятого коммита поиска; её инструкция отдельно объясняет запрос на слияние и подготовку автоматической проверки.

Не добавляй в историю проекта пароли, ключи, файлы .env и реальные данные студентов. Для заданий используй только учебные заявки.
