# 05. Merge Request, CI, review и skill приёмки

**Цель:** Довести изменение до воспроизводимой передачи другому человеку.

**Рабочая ветка:** `feature/title-sort`

## Требование

Добавить сортировку заголовков `А–Я` и `Я–А` без изменения исходного массива.

## Задание

1. Создайте задачу и feature-ветку.
2. Попросите агента реализовать и экспортировать `sortTicketsByTitle(tickets, direction)`.
3. Допустимые направления: `asc`, `desc`; неизвестное значение вызывает `RangeError`.
4. Создайте `.agents/skills/acceptance-check/SKILL.md` и запустите его при наличии поддержки skills. Без доступа выполните те же шаги вручную и запишите результат.
5. Запустите `npm test` и проверьте UI.
6. Создайте Merge Request по шаблону, дождитесь CI.
7. Выполните `/review` или отдельный AI-review. Каждое замечание классифицируйте: `блокирует`, `полезно`, `предпочтение`, `ложное`.
8. Исправляйте только подтверждённые проблемы и зафиксируйте финальный commit.

## Успешный результат

- `npm test` завершается с кодом `0`; после реализации проходят **19 тестов**: 5 базовых + 5 фильтра + 5 поиска + 4 сортировки;
- при `asc` первый title равен `Не включается проектор`, последний — `Сломалась клавиатура`;
- `desc` даёт точный обратный порядок ID относительно `asc`;
- направление `sideways` вызывает `RangeError`;
- исходный массив не мутируется;
- файл `.agents/skills/acceptance-check/SKILL.md` существует и требует сверить критерии, запустить тесты и назвать непроверенные риски;
- Merge Request содержит разделы **что изменено / как проверить / что проверено / что не проверено / риски**;
- GitVerse CI зелёный на финальном commit;
- в отчёте есть таблица всех замечаний review. Если review не выдал замечаний, студент задаёт минимум **2 целевых вопроса** о рисках сортировки и фиксирует ответы как `подтверждено` или `не подтверждено`.

## Не засчитывается, если

- сортировка меняет исходный массив;
- MR создан, но CI красный или относится к другому commit;
- студент автоматически принимает каждое замечание AI-review без проверки;
- skill существует только как файл, но студент не может объяснить его шаги;
- в MR нет честного раздела «что не проверено».

## Что сдавать

- ссылка на Merge Request и зелёный pipeline;
- `REPORT.md` с выводом 19 тестов;
- `.agents/skills/acceptance-check/SKILL.md`;
- таблица review: `замечание → категория → доказательство → решение`.

## Индивидуальный вопрос

Почему второй AI-review не является доказательством правильности, даже если он написал PASS?

## Что принимает преподаватель

- точные результаты asc/desc совпадают с контрактом
- `npm test` показывает 19 успешных тестов
- MR и зелёный CI относятся к финальному commit
- review-замечания оценены человеком, а не приняты автоматически
