# 06. Готовая AI-подсказка и индивидуальная защита

**Цель:** Подключить готовую AI-подсказку, проверить явное применение и ручной путь при отказе, показать один новый пример и объяснить решение без агента.

**Рабочая ветка:** `feature/ai-triage`

## Перед подключением

Продолжай свою накопленную папку с принятыми поиском, формой и сохранением SQLite. **05 необязателен**.

**OpenCode** помогает работать с файлами проекта; **подсказка на странице приложения** подключается отдельно и не использует настройки OpenCode.

Категория означает вид проблемы, приоритет её срочность. Названия ниже помогут отличить готовые действия приложения от собственной правки:

- **Apply**, кнопка **Применить категорию и приоритет**.
- **Create**, кнопка **Создать**.
- **Фокус**, элемент, который сейчас принимает клавиши.

Преподаватель после отдельного разрешения передаёт `H3/final` или `H4/final`. Публикация инструкций всех шести работ не разрешает выдачу или публикацию закрытых комплектов. Закрытые пути: `dist/handoffs/H3/final`, `dist/handoffs/H4/final`, не `public`.

Это полностью работающий накопительный `reference`: `triageTicket`, явное Apply, provider/route/UI и тесты уже готовы. Студент сохраняет свой проект при интеграции и делает **отдельную правку только** `src/app.js`: после явного Apply фокус на `category` для ручной проверки.

Сам запрос подсказки не меняет поля, фокус или БД. Готовые обработчики заново подключать не нужно; их работу нужно понять и объяснить.

Полный reference распаковывают **отдельно для сравнения**, не поверх проекта. Для `recovery` нужна новая папка с явной отметкой восстановления; пропущенные проверки не закрываются автоматически.

Пакеты не публичны и не выдаются по наступлению даты. Подготовка и проверка преподавателем выполняются заранее.

`H3/final` и `H4/final`, имена выдаваемых комплектов. Выбирать по ним расписание не нужно. `manifest.json` перечисляет содержимое и версии.

- **Foundation** означает готовую основу формы и хранения.
- **Final** добавляет готовую подсказку.
- **Reference** означает пример преподавателя для сравнения, а не твою выполненную работу.

## Как устроена подсказка

**OpenCode**, агент для работы с кодом, читает файлы и выполняет разрешённые команды. **Модель** обрабатывает переданный текст, **провайдер** предоставляет доступ к модели.

У приложения свой источник подсказки. Для задания его заменяет тестовая функция без модели и облака.

Например, в маршруте OpenCode Inception название провайдера, Mercury 3 название модели у него. Их выбор в OpenCode не подключает модель к кнопке приложения и не подтверждает доступность сервиса.

Тестовую замену источника ответа называют **mock**: она возвращает подготовленный результат, чтобы проверить действия формы без реальной модели.

**API**, набор адресов и правил обмена страницы с сервером. `POST` означает отправку данных, **JSON** записывает данные по именам полей.

Приложение передаёт подсказке **только вымышленные** `title` (**Краткий заголовок**) и `description` (**Описание**). `location` (**Место**) ей не передаётся.

**Контракт** означает согласованный формат данных и ожидаемые результаты. Готовая часть приложения проверяет поля:

- `category` («Категория»): `equipment` = «Оборудование», `network` = «Сеть», `software` = «ПО» (программное обеспечение), `access` = «Доступ», `other` = «Другое».
- `priority` («Приоритет»): `low` = «Низкий», `normal` = «Обычный», `high` = «Высокий».
- `summary`: короткое пояснение длиной **5–160 символов после удаления пробелов по краям** (`trim`). Оно не заменяет описание заявки.

**Enum** означает закрытый список значений. Например, категория «Сеть» передаётся как `network`; произвольное `internet` недопустимо.

**HTTP-статус**, число в заголовках ответа сервера. `POST /api/triage` даёт `200` для допустимого предложения. Тело JSON содержит `available: true` («доступно») и `suggestion` с `category`/`priority`/`summary`.

При недоступности статус `503`, `available: false`, а `reason` указывает причину:

- `invalid_response`: «неверный ответ».
- `provider_error`: «сбой провайдера».
- `provider_unavailable`: «провайдер не настроен».
- `title_required`: «нужен заголовок».

Испорченный JSON самого запроса даёт `400` `invalid_json`. **Разрешённый формат ещё не доказывает, что предложение подходит по смыслу**.

Предложение отображается отдельно:

- **До применения** поля и БД прежние.
- **После применения** меняются только `category`/`priority`, но заявка ещё не создана.
- **Создать** отдельно отправляет обычный `POST /api/tickets`.

Можно отказаться от предложения, исправить поля вручную и создать. При `invalid/error` форма остаётся рабочей.

Пока запрос выполняется, страница показывает **Ожидаем подсказку**. Ручное создание доступно и в этом состоянии: ждать AI не обязательно. В `demo` подготовленный ответ может прийти сразу, поэтому намеренно замедлять его не нужно.

**Apply** означает **Применить категорию и приоритет**, **Create** означает **Создать**. Только Create сохраняет запись в SQLite и возвращает `201` с `ID`, номером созданной заявки.

**Фокус**, активный элемент для клавиатуры: в текстовом поле виден курсор, в списке стрелки меняют выбор. После Apply твоя правка переводит фокус в категорию для проверки; после Create сохраняется прежний возврат в заголовок.

Если изменился заголовок или описание, прежняя подсказка скрывается. Она могла относиться уже к другому тексту. Запоздавший ответ на старый текст тоже игнорируется.

Это не отменяет вручную выбранные или уже применённые `category`/`priority`. Различай причины, по которым подсказку нельзя использовать:

- **Stale**, «устаревшая»: ответ для «нет сети» уже не относится к описанию «сломан проектор». Видимый пример ниже: после добавления «Уточнение» блок исчезает, выбранные поля остаются.
- **Invalid**: ответ нельзя принять по формату, например вместо данных пришло `not-json`.
- **Error**: тестовая функция завершилась с ошибкой.

**Во всех случаях ручная форма остаётся доступной**.

Для проверки выбираем один из режимов через `SERVICEDESK_AI_MODE`:

- `demo` («демонстрация») всегда возвращает `network/high`, даже если текст о проекторе: это фиксированное «Сеть / Высокий».
- `invalid` («недопустимый ответ») возвращает `not-json`: ответ пришёл, но не читается в требуемом формате.
- `error` («ошибка выполнения») имитирует сбой функции.

**Во всех трёх режимах модель и облако не вызываются**. Реальный вызов и ключ необязательны и не влияют на оценку. Не помещай ключи OpenCode или облака в сообщения, исходники, Git или снимки.

## Проверка трёх режимов

В терминале сервера **оставь прежний** `SERVICEDESK_DB`; в новом терминале сначала задай тот же путь, сохранённый в работах 03–04. `HANDOFF` дополнишь после проверки: он не нужен, чтобы сейчас найти уже известный путь.

Перед каждой сменой режима останови Node `Ctrl+C` и дождись строки PowerShell. Выполняй строки по одной, без цепочек команд.

```powershell
$env:SERVICEDESK_AI_MODE = 'demo'
npm.cmd start
```

Открой адрес из вывода сервера. В форме **Новая заявка** заполни поля:

- **Краткий заголовок**: «Учебная заявка: нет сети на стенде А».
- **Описание**: «Вымышленный стенд А не открывает учебную страницу».
- **Место**: «Учебный стенд А».
- **Категория**: «Другое».
- **Приоритет**: «Низкий».

Никаких реальных имён, контактов или паролей.

Нажми `F12` и выбери **Сеть / Network**, список запросов страницы к серверу. В строке запроса:

- **Headers («Заголовки»)** показывает HTTP-статус.
- **Response («Ответ»)** показывает содержимое JSON.

Читай статус и тело ответа отдельно. Например, `503` сообщает отказ подсказки, а JSON `{"available":false,"reason":"invalid_response"}` объясняет причину: ответ тестового источника не прошёл проверку. Ответ API при этом остаётся правильным JSON.

Одинаковый текст отказа на странице может сопровождаться другим `reason`, поэтому его проверяют в **Response**.

1. Перейди `Tab` к **Предложить с AI** и нажми `Enter`. Сам ответ не должен переводить фокус в другое поле. В **Network** найди `POST /api/triage` с `200`, `available: true` и предложением `network/high`. В форме по-прежнему «Другое / Низкий», записи ещё нет.
2. Нажми **Отказаться**: блок скрывается без изменения формы и создания. Запроси новое предложение и нажми **Применить категорию и приоритет**. Теперь в форме «Сеть / Высокий», остальные поля прежние. **Без щелчка** нажми стрелку: меняться должна категория. Верни «Сеть». `POST /api/tickets` ещё нет.
3. Допиши «Уточнение» в описание. Старое предложение скрылось, выбранные `category`/`priority` остались. Готовые тесты отдельно проверяют запоздавший ответ; ожидать медленного ответа в `demo` не нужно.
4. Нажми **Создать**. Ожидаются сообщение с `ID` и `POST /api/tickets` с `201`. После очистки формы начни ввод **без щелчка**: текст появляется в заголовке. Удали пробный текст. Точный `ID` зависит от состояния базы; `113` возможен лишь при первом создании на чистой исходной БД.

Останови `Ctrl+C`, затем:

```powershell
$env:SERVICEDESK_AI_MODE = 'invalid'
npm.cmd start
```

После обновления страницы запроси подсказку. Ожидается `503` `invalid_response`, предложение не применяется.

**Заполни поля вручную и создай заявку** через обычный `POST` `201`.

Останови `Ctrl+C`, затем:

```powershell
$env:SERVICEDESK_AI_MODE = 'error'
npm.cmd start
```

Запроси подсказку: `503` `provider_error`, понятное сообщение. **Создай ещё одну заявку вручную**, ожидается `201`.

Остальные отказы (нет provider, пустой `title`, неверные типы/enum/`summary`, испорченный JSON) проверяются готовыми контрактными тестами.

При расхождении отправь агенту **ввод, ожидание и факт**, согласуй исправление и повтори затронутый режим. Искусственная ошибка или обязательное уточнение не нужны.

## Подготовить HANDOFF и индивидуальную защиту
