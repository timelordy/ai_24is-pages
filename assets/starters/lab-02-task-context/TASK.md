# 02. Из просьбы заказчика делаем проверяемую задачу

**Цель:** До изменения кода определить требования, неизвестные данные, границы и способ приёмки.

**Рабочая ветка:** `lab/02-task-context`

## Исходная просьба

> Добавьте фильтр заявок по статусу. Должно быть удобно.

## Задание

1. Прочитайте `BRIEF.md`, `REQUIREMENTS.md` и текущее приложение.
2. Создайте задачу GitVerse по шаблону из `gitverse/issue-template.md`.
3. Самостоятельно отметьте, какие решения уже заданы, а каких данных нет.
4. Попросите GigaCode найти неоднозначности и связанные файлы. Не просите писать код.
5. Сформулируйте минимум два содержательных уточняющих вопроса.
6. Зафиксируйте принятое учебное решение: значения фильтра `Все`, `Открытые`, `Закрытые`.
7. Запишите четыре критерия приёмки, включая пустой результат.
8. Проверьте `git diff`: исходный код не должен измениться.

## Минимум

- задача GitVerse;
- два вопроса;
- границы изменения;
- четыре критерия приёмки;
- пустой diff.

## Индивидуальный вопрос

Какое решение агент мог бы сам придумать, если бы вы не уточнили поведение неизвестного статуса?


## Что принимает преподаватель

- задача отделяет факты от решений
- есть не менее двух вопросов
- критерии можно воспроизвести
- исходный код не изменён
