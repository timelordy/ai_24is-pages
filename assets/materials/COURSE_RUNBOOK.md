# Регламент курса GitVerse + GigaCode

## Главный принцип

Одна новая способность агента на пару и **один заранее определённый Definition of Done**. Студент до работы знает конкретные значения, команды и артефакты, по которым будет решаться PASS/FAIL.

Фраза «кажется, получилось» не используется как критерий. Сообщение агента «готово» тоже не является критерием.

## Расписание после отмен первых встреч

Все подгруппы выполняют **6 одинаковых обязательных работ**.

- у 24ИС02/1 и 24ИС03/2 настройка GitVerse/GigaCode входит в работу 01;
- у 24ИС02/2 и 24ИС03/1 встреча 21 сентября используется как вводная настройка без отдельной обязательной лабораторной;
- после вводной эти две группы также выполняют работы 01–06 по общей программе.

## Ритм обычной пары

| Минуты | Действие |
|---|---|
| 0–10 | Прочитать Definition of Done и предсказать контрольные результаты |
| 10–20 | Один пример преподавателя: вход → действие → проверка |
| 20–65 | Работа в персональных форках с агентом |
| 65–80 | `git diff`, локальные тесты, ручные сценарии, CI/MR |
| 80–90 | Индивидуальный вопрос и фиксация PASS/FAIL |

На первой обязательной работе установка может занять больше времени только у групп без отдельной вводной. После 35-й минуты не чинить один ПК всей группой: студент пересаживается или работает в паре со сменой ролей.

## Основной и резервный маршруты

**Основной:** GitVerse Lab → локальный VS Code + GigaCode → GitVerse CI/CD.

**При наличии доступа:** GigaCode Session Plan/Build, `/init`, `/review`, skills.

**Резерв:** заранее подготовленный учебный ПК или работа в паре. Демонстрация преподавателя не засчитывается как личный агентный прогон.

## Правила Definition of Done

В каждом `TASK.md` обязательны:

1. **Успешный результат** — точные входы/выходы, число тестов, команды и артефакты.
2. **Не засчитывается, если** — список ложных успехов.
3. **Что сдавать** — минимальный набор доказательств.
4. **Что принимает преподаватель** — четыре коротких контрольных пункта.

Если задача допускает несколько решений, проверяется внешний контракт, а не конкретная реализация.

## Правила сложности

- одно функциональное изменение за пару;
- новые библиотеки запрещены без отдельного согласования;
- проект не переписывается на фреймворк;
- студент до запуска агента знает ожидаемый результат;
- агентный ответ проверяется тестом, diff, CI или воспроизводимым сценарием;
- `AGENTS.md` содержит только специфичные для проекта правила;
- skills описывают повторяемую процедуру, а не заменяют проверку человеком.

## Приём

Работы 01–05 принимаются по Definition of Done, артефактам GitVerse и короткому индивидуальному вопросу. Работа 06 включает индивидуальную защиту на новом входе.

Если в подгруппе больше 16 студентов, часть индивидуальных объяснений по работам 04–05 принимается по ходу занятий, чтобы финальная пара не превратилась в очередь к одному преподавателю.

## До запуска

1. Провести пилот на трёх студентах разной подготовки и одном учебном ПК.
2. Проверить регистрацию, GigaCode, clone/push, Node.js и GitVerse CI.
3. Уточнить, кому доступны Sessions, GigaCode-разработчик и MCP.
4. Создать шесть шаблонных репозиториев из `dist/gitverse-repos`.
5. Создать модуль и шесть обязательных заданий в GitVerse Lab.
6. Для 24ИС02/2 и 24ИС03/1 использовать 21 сентября для вводной настройки.
7. Включить задачи, CI/CD и защиту основной ветки.
8. Не включать автоматический платный перерасход облачной среды без отдельного решения кафедры.
