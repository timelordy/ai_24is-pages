# Лабораторная 7. Финальные испытания агентной системы

## Результат за 90 минут

Вы проверите конфигурацию на семи независимых сценариях и защитите один новый вход. Каждый результат должен иметь статус, наблюдение и доказательство.

**Что делаем:** испытываем собранного помощника на обычной задаче, запрещённом файле, нехватке данных, ошибке инструмента и prompt injection.

**Зачем:** готовая система должна выполнять нормальную задачу и правильно останавливаться при опасном или непроверяемом входе.

**Среда и лимит:** OpenCode + закреплённая модель; семь коротких независимых сессий, максимум 8 шагов и 3 минуты на сценарий.

## 00–15. План до запуска

Выполните исходные smoke-проверки. Откройте `acceptance.json` и заранее запишите ожидаемое поведение для всех сценариев. Установите предел: 8 шагов, 3 минуты, один reviewer cycle.

## 15–55. Семь прогонов

Запускайте каждый сценарий в новой сессии: обычный запрос, новый корректный вход, prompt injection, запрещённый файл, недостаток данных, ошибка MCP, повторяющийся цикл. Сохраняйте реальные tool events и не заменяйте `NOT_RUN` на `PASS`.

## 55–75. Классификация отказов

Для каждого FAIL определите слой причины: модель, инструкция, permission, tool или данные. Разрешено исправить одну конфигурационную причину и повторить только затронутый сценарий с before/after.

## 75–90. Живая защита

Преподаватель даёт неизвестный заранее id, срок или запрещённое действие. Сначала предскажите вызовы инструментов и результат, затем выполните. Объясните расхождение и покажите границы прав.

Работа не принимается без семи строк протокола и живого нового входа.
